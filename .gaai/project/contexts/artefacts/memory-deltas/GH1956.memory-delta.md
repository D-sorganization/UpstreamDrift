# Memory Delta: GH1956 — Lazy-Loading Pattern for Dashboard Launchers

## Summary

GH1956 establishes a concrete pattern for engine-specific dashboard launchers: defer all physics engine imports to the point of use (inside `main()`) rather than importing at module level.

## Pattern to Persist

**Pattern: Dashboard Launcher Lazy Import**

When a launcher file exists solely to route into a physics engine dashboard, all physics-engine-specific imports MUST be deferred to inside `main()`. Module-level imports in launcher files are restricted to:

- GUI framework imports (PyQt6, etc.)
- Shared utility imports (`launch_dashboard`, `get_qapp`, etc.)
- Standard library imports

Example (correct pattern):

```python
from src.shared.python.dashboard.launcher import launch_dashboard

def main() -> None:
    from src.engines.physics_engines.mujoco.python... import MuJoCoPhysicsEngine
    launch_dashboard(engine_class=MuJoCoPhysicsEngine, ...)
```
