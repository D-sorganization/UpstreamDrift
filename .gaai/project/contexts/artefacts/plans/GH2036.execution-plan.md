# GH2036 Execution Plan: 526 source modules have no corresponding test file

## Story Summary

624 source modules (of 942 total) currently lack a matching `test_<module>.py` file — a 66%
module-level gap in test coverage. GH1949 previously addressed 3 modules (screw_theory and
engine_availability). This Story delivers the next targeted reduction by adding well-structured
unit tests for 3 high-value modules in `src/shared/python/analysis/`, which are pure numpy/stdlib
with no GUI or engine dependencies.

## Target Modules

1. `src/shared/python/analysis/dataclasses.py` → `tests/shared/python/analysis/test_dataclasses.py`
2. `src/shared/python/analysis/angular_momentum.py` → `tests/shared/python/analysis/test_angular_momentum.py`
3. `src/shared/python/analysis/energy_metrics.py` → `tests/shared/python/analysis/test_energy_metrics.py`

Plus: `tests/shared/python/analysis/__init__.py` (empty, required for pytest discovery)

## Approach

Targeted unit tests using pure numpy fixtures. No GUI, no physics engine, no display server.
All tests use `pytest.mark.unit` marker and mock only what is needed to isolate the unit under test.

## Implementation Sequence

### Step 1: Add **init**.py for analysis test directory

- File: `tests/shared/python/analysis/__init__.py`
- Content: Empty (enables pytest discovery)

### Step 2: Add test_dataclasses.py

- File: `tests/shared/python/analysis/test_dataclasses.py`
- Tests:
  - `MethodCitation` frozen dataclass fields and optional fields
  - Pre-defined citations (CITATION_SEGMENT_TIMING, CITATION_X_FACTOR, etc.) have correct fields
  - `KinematicSequenceInfo` is alias for `SegmentTimingInfo`
  - `CITATION_KINEMATIC_SEQUENCE` is alias for `CITATION_SEGMENT_TIMING`
  - `validate_timing_cross_engine` — happy path, mismatch length, within/exceeding tolerance
  - `validate_angle_cross_engine` — happy path, shape mismatch, within/exceeding tolerance
  - All dataclasses construct without error: PeakInfo, SummaryStatistics, SwingPhase,
    SegmentTimingInfo, GRFMetrics, AngularMomentumMetrics, StabilityMetrics,
    CoordinationMetrics, JointPowerMetrics, ImpulseMetrics, RQAMetrics,
    SwingProfileMetrics, PCAResult, JointStiffnessMetrics, JerkMetrics
- Marker: `pytestmark = pytest.mark.unit`

### Step 3: Add test_angular_momentum.py

- File: `tests/shared/python/analysis/test_angular_momentum.py`
- Tests:
  - Returns None when `angular_momentum` attribute is None or empty
  - Computes correct peak_magnitude for known input
  - Computes correct mean_magnitude
  - Computes correct component peaks (peak_lx, peak_ly, peak_lz)
  - Variability is 0 when angular momentum is constant
  - Variability is non-negative
  - All postconditions hold (peak_magnitude >= 0, mean_magnitude >= 0, etc.)
  - Works when `times` is None (peak_time defaults to 0.0)
- Strategy: Create a minimal mock object with `angular_momentum` and `times` attributes,
  call `compute_angular_momentum_metrics` directly
- Marker: `pytestmark = pytest.mark.unit`

### Step 4: Add test_energy_metrics.py

- File: `tests/shared/python/analysis/test_energy_metrics.py`
- Tests:
  - Raises `ValueError`/`AssertionError` when kinetic_energy is empty
  - Raises when potential_energy is empty
  - Raises when arrays have different lengths
  - Raises when kinetic_energy has negative values
  - Correct max_kinetic_energy, max_potential_energy, max_total_energy
  - energy_efficiency computed correctly when club_head_speed available
  - energy_efficiency is 0.0 when club_head_speed is None
  - energy_drift = last - first total energy
  - All returned metrics are finite
  - energy_efficiency >= 0
- Strategy: Create minimal mock object with optional `club_head_speed` attribute
- Marker: `pytestmark = pytest.mark.unit`
