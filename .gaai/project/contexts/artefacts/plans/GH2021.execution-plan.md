# GH2021 Execution Plan: Cross-Engine Perturbation Consistency

## Story Summary

Bug: When running `CrossEnginePerturbationRunner` with identical `additive` noise on a
standard torque profile, massive inconsistency (CV > 1.0) is observed in final simulation
states across `myosuite`, `mujoco`, and the baseline `pendulum` engines.

## Root Cause Analysis

Three root causes for divergence:

1. **Mismatched integration timesteps**: `MyoSuitePhysicsEngine._dt = 0.002` (default),
   `DOUBLE_PENDULUM_XML` uses `DEFAULT_TIME_STEP = 0.001`, and `PendulumPhysicsEngine.step()`
   defaults to `0.01`. The bug report mentions `dt=0.01` as the standard.

2. **Mismatched physical parameters**: The `DoublePendulumDynamics` uses golf-swing-specific
   masses (7.5kg arm, 0.35kg club) while MuJoCo XML defines different distributed masses via
   geom elements. No standardized "cross-engine comparison" parameter set exists.

3. **Missing `CrossEnginePerturbationRunner`**: The class referenced in the bug report does not
   exist. The existing `perturbation_analysis.py` is single-engine and protocol-based. A
   cross-engine runner needs to: (a) normalize initialization parameters, (b) apply identical
   additive noise to all engines, (c) collect unified metrics, and (d) report CV per metric.

## Implementation Plan

### Step 1: Create `CrossEnginePerturbationRunner`

**File**: `src/shared/python/pendulum_simulator/cross_engine_perturbation.py`

Create a new module with:

- `CrossEngineSimConfig` dataclass: `t_end=1.5`, `dt=0.01`, `noise_type="additive"`,
  `noise_amplitude=0.1`, `n_trials=10`, `seed=42`
- `CrossEngineRunResult` dataclass: holds per-engine metrics dict
- `CrossEnginePerturbationRunner` class:
  - `__init__(self, config: CrossEngineSimConfig)` — DbC: validate config
  - `register_engine(self, name: str, engine: PhysicsEngine)` — LOD: delegate to engine
  - `run_comparison(self, base_torque_profile: list[float]) -> dict[str, CrossEngineRunResult]`
    — applies identical additive noise, runs each engine for t_end/dt steps at dt, collects
    metrics: `total_energy_final`, `end_effector_speed_final`, `peak_end_effector_speed`,
    `trajectory_rmse` (vs baseline)
  - `compute_cv_summary(self, results: dict) -> dict[str, float]` — CV per metric

All engines are stepped with `dt=0.01` regardless of internal default.
All engines are reset and initialized to zero state before each trial.

### Step 2: Standardize PendulumPhysicsEngine defaults

**File**: `src/engines/physics_engines/pendulum/python/pendulum_physics_engine.py`

The `step()` method already accepts `dt` parameter — no change needed. But the default
step value (0.01) in the step docstring should be made explicit via a module constant
`STANDARD_DT = 0.01` referenced consistently.

Add `STANDARD_DT: float = 0.01` constant to the pendulum engine module for clarity.

### Step 3: Add `additive` noise support to perturbation infrastructure

**File**: `src/shared/python/pendulum_simulator/perturbation_analysis.py`

The `perturb_torque_coeffs` function handles polynomial coefficient perturbation.
For the cross-engine runner, we need `additive` noise on a raw torque _profile_ (not
polynomial coefficients). Add a new function:

```
def perturb_torque_profile(
    profile: np.ndarray,
    noise_amplitude: float,
    noise_type: str = "additive",
    seed: int | None = None,
) -> np.ndarray
```

Where `noise_type="additive"` applies zero-mean Gaussian noise with std=noise_amplitude.

### Step 4: Write tests (TDD)

**File**: `tests/unit/shared_python/test_cross_engine_perturbation.py`

Tests (all unit tests, no external engine dependencies, mock PhysicsEngine protocol):

1. `test_cross_engine_sim_config_defaults` — default config has correct values
2. `test_cross_engine_sim_config_validation` — invalid dt/t_end/noise_amplitude raises ValueError
3. `test_register_engine` — register mock engine, verify name appears in runner
4. `test_run_comparison_single_engine_deterministic` — same seed → same result
5. `test_run_comparison_identical_noise_applied` — two engines with same dynamics get same noise
6. `test_compute_cv_summary_zero_variance` — identical engines → CV near zero
7. `test_compute_cv_summary_non_zero` — engines with different physics → CV > 0
8. `test_perturb_torque_profile_additive` — shape preserved, mean noise near zero
9. `test_perturb_torque_profile_seed_reproducibility` — same seed → same output
10. `test_perturb_torque_profile_zero_amplitude` — zero amplitude → no change

### Step 5: Run ruff check/format

```bash
python3 -m ruff check src/shared/python/pendulum_simulator/cross_engine_perturbation.py \
    src/shared/python/pendulum_simulator/perturbation_analysis.py \
    tests/unit/shared_python/test_cross_engine_perturbation.py
python3 -m ruff format src/shared/python/pendulum_simulator/cross_engine_perturbation.py \
    src/shared/python/pendulum_simulator/perturbation_analysis.py \
    tests/unit/shared_python/test_cross_engine_perturbation.py
```

## Edge Cases

- Engine step() called with explicit dt=0.01 to override internal defaults
- Engines reset between trials to prevent state accumulation
- Zero noise amplitude produces deterministic (baseline) results
- CV computation handles zero mean (returns 0.0, not division by zero)

## Risk Register

| Risk                                         | Mitigation                                                             |
| -------------------------------------------- | ---------------------------------------------------------------------- |
| MuJoCo/MyoSuite not installed in test env    | Use mock PhysicsEngine protocol — no real engine needed for unit tests |
| Trajectory RMSE requires a "baseline" engine | Use first registered engine as baseline                                |
| Engine state dimensionality varies           | Normalize to 2-DOF: theta1, theta2, omega1, omega2                     |

## Rollback Boundaries

- New file `cross_engine_perturbation.py` can be deleted without any impact on existing code
- `perturbation_analysis.py` change is purely additive (new function, no modification to existing)
- No changes to engine files or XML models
