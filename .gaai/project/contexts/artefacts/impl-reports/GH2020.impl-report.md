## Rules Applied

- Lazy-loading pattern: all heavy imports (PyQt6, Matplotlib, engine modules) deferred inside constructors/functions per project convention
- DRY: reuses `CrossEnginePerturbationRunner`, `CrossEngineSimConfig`, `SteppableEngine` from `cross_engine_perturbation.py`
- DbC: preconditions validated in `_run_headless`, `_StubEngine.__init__`, `CrossEngineSimConfig.__post_init__`
- LOD: no method chains > 2 levels
- No `print()` in `src/`

## Architecture Notes

- `CrossEngineDashboardWindow` is intentionally not a subclass of the existing
  `launch_dashboard()` interface because the cross-engine data model
  (`CrossEngineSimConfig`) does not map to the existing single-engine interface.
- `_StubEngine` allows graceful degradation when real physics packages are absent,
  making the dashboard functional in CI and dev environments lacking full engine installs.
- GUI runs comparison synchronously on the main thread (blocking with
  `QApplication.processEvents()` for feedback). For long runs the implementation
  could be moved to a QThread — documented as a follow-up concern, not required by ACs.
