## Summary
Move launcher behavior to Docker-first while preserving usability when Docker is unavailable.

## Problem
Launcher currently defaults to local mode and prompts users into Docker only after dependency failures. This is opposite of desired product path and causes inconsistent runtime behavior.

## Scope
- Default launcher execution mode to Docker when Docker is available
- Keep local/WSL as explicit fallback options
- Improve user messaging for missing Docker / missing image
- Persist and respect user override choices

## Acceptance Criteria
- [ ] Docker mode auto-selected on fresh start if Docker is available
- [ ] If Docker is unavailable, launcher falls back without hard failure
- [ ] Status UI clearly indicates active runtime mode
- [ ] Unit/integration tests for mode selection behavior

## Rollback / Reversibility
- Feature flag/env var to disable Docker-first default
- Existing local/WSL launch paths remain intact
