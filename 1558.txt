## Summary
Introduce runtime tiers so core product users get a smaller, portable image while advanced users can opt into heavy ML/training dependencies.

## Problem
A single monolithic environment is expensive to build, pull, and troubleshoot, especially for users without high-end GPU setups.

## Scope
- Define `core` profile: product runtime for app/API/simulation workflows
- Define optional `training` profile: heavy ML dependencies
- Add compose/profile docs for selecting runtime tier
- Ensure core path works on typical developer hardware

## Acceptance Criteria
- [ ] Distinct Docker build targets/profiles documented and tested
- [ ] Core profile excludes heavy ML training dependencies
- [ ] Training profile is optional and versioned
- [ ] Clear compatibility matrix (CPU/GPU, OS, Docker requirements)

## Rollback / Reversibility
- Keep existing all-in-one build target until tiered flow is stable
- Allow users to opt into old monolithic behavior during transition
