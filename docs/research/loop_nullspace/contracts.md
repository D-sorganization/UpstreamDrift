# Per-Child Contract Appendix for NSX-02 to NSX-62

This appendix is the binding contract for the `tier:cli` children of epic
#12593 and records the contract of the `tier:strong` and `tier:ollama`
children where they constrain others. It pins signatures, preconditions,
postconditions and named golden fixtures. Formulas are in
`loop_nullspace.tex`; golden files live in
`tests/fixtures/loop_nullspace/goldens/` and are regenerated by
`docs/research/loop_nullspace/derivations/generate_goldens.py`. A child must
not change a golden value to pass; if the specification is ambiguous, ask on the
issue.

## Shared Conventions

- Import through the canonical root, for example
  `from src.shared.python.loop_nullspace.contracts import ClosedLoopSnapshot`.
  Preconditions use `src.shared.python.core.contracts.require` and
  postconditions use `ensure`.
- SI units. Arrays are `float64`, read-only after construction.
- Coordinate order is the snapshot's `coordinate_order`; row order of closure
  quantities is `[fx fy fz tx ty tz]` in the grip frame (rule R8). Planar
  closures use the rows named in `LoopTopology.closure_rows`.
- Numerical rank: relative singular-value tolerance `1e-10` of the largest
  singular value of the scaled matrix, with characteristic scales
  `F_c = 100 N` and `M_c = 5 N m` (convention `C-SCALE-FORCE-MOMENT`).
- Goldens are compared with `rtol = 1e-12`, `atol = 1e-13`, except fields the
  golden marks exact (rational strings), which compare exactly.
- Every golden JSON carries `"schema": "loop-nullspace-golden/1"` and a `name`.

## NSX-02 Canonical Closure Convention (#12551)

Module `loop_nullspace/closure_convention.py`.

```python
@dataclass(frozen=True)
class NativeClosureConvention:
    row_order: Literal["lin_ang", "ang_lin"]
    frame: Literal["LOCAL", "WORLD"]
    point: str            # reference point of the linear rows
    relative_sign: Literal[1, -1]   # +1: V_a - V_b, -1: V_b - V_a

def to_canonical_closure(
    jacobian: ArrayLike, drift: ArrayLike, *,
    native: NativeClosureConvention,
    native_frame_rotation: ArrayLike,   # world <- native LOCAL frame; identity for WORLD
    grip_frame_rotation: ArrayLike,     # world <- grip frame
    native_reference_point: ArrayLike,  # world position
    grip_reference_point: ArrayLike,    # world position
) -> tuple[np.ndarray, np.ndarray]: ...
```

- Preconditions: `jacobian` is `6 x n`, `drift` is length 6, both rotations are
  orthonormal with determinant +1, all values finite.
- Postconditions: output `J_c` is `6 x n` and `Jdot_v` length 6 in the
  canonical convention. `J_c = C J_native` with `C` the conversion matrix of
  the specification (`golden closure_convention`, key
  `C_native_to_canonical`). Power is preserved: `lambda_native . (J_native v)`
  equals `lambda_c . (J_c v)` with `lambda_native = C^T lambda_c`.
- Round trip: an inverse function reproduces the native Jacobian exactly.
- Drift: `Jdot_v` is converted with the same `C`. This is exact only on
  `J_c v = 0`; admission (NSX-14) precedes use.
- Tests: golden `closure_convention` for all four native conventions (a),
  power invariance (b), round trip (c), per-engine canonical equality on states
  projected with `project_to_closure` (d, `requires_*`).

## NSX-04 Torque Capacity (#12553)

`capacity_for(coordinate_order, subject, actuated=None) -> CapacityVector`
(`loop_nullspace/capacity.py`). Preconditions: non-empty, duplicate-free
`coordinate_order`; `subject` a `CapacitySubject(mass_kg, stature_m, sex)`
(male only; no other table is registered); every actuated coordinate has an
entry in both directions, otherwise `ValueError` listing the missing
`slot:direction` pairs. `actuated` defaults to all coordinates except root
translations (forces, not torques). Postconditions: positive finite capacities
per direction; `assumed_slots`, `verified_slots` and `warnings` surface every
ASSUMED value, which is also logged.

Registry section `torque_capacity` (schema in the registry's `schema_note`):
one entry per coordinate and direction (`negative` or `positive` generalised
coordinate sign). Scaling rules: `bw_height_normalized` computes
`tau = c * mass_kg * 9.80665 * stature_m` (Anderson 2007 normalisation, body
weight read as a force); `none` returns the population value unchanged.
`tau_max_nm` stores the value for the reference subject (78 kg, 1.71 m).
VERIFIED requires a number read in the cited source and a sign-to-motion mapping
that is unambiguous from the spec; where only the axis or sign convention is
unresolved the entry is ASSUMED even though a source number is quoted.
Each entry records `axis_mapping` (`hinge`, or `approximate-at-reference-pose` for
gimbal and universal joints) with `axis_evidence` (frame derivation or file:line).
Shoulder axes resolve to horizontal abduction/adduction (X), flexion/extension
(Y) and axial rotation (Z), but no readable source covers them, so they stay
ASSUMED. Where the sign is unresolved but a flexion/extension pair is verified, the
smaller value is applied to both directions (`basis` field). Capacities are
male population priors, not subject measurements.

  disjoint and covering the coordinates; `S` is a selection of actuated
  coordinates consistent with `actuated_indices`.

  `hypotheses`; registry resolution happens at display time via
  `require_verified_for_display`. A bare string is a `TypeError`.
- Arrays are read-only (writing raises `ValueError`).
- Import without any physics engine installed.

## NSX-13 Snapshot From Adapter (#12558)

```python
def snapshot_from_adapter(adapter: BaseEngineForceAdapter, q, v, a, *,
                          input_provenance: InputProvenance) -> ClosedLoopSnapshot
```

Raises `CapabilityUnavailable` unless
`adapter.capability(Capability.CLOSED_LOOP_SNAPSHOT) is FULL`. New adapter
methods: `compute_closure_drift(q, v) -> ndarray (6,)`,
`closure_wrench_frame(q) -> (R (3,3), origin (3,))`,
`club_inertia_split() -> (bare, welded_hands)`, and the
`native_closure_convention` attribute. Postconditions: snapshot equals the
NSX-12 spatial fixture built independently; the corrected
`verify_acceleration_parity` agrees with `constraintDynamics` to `1e-9`
scaled.

Implementation notes (Pinocchio reference, #12558):

- The optional members live in `ClosedLoopSnapshotAdapter` (a separate
  protocol, so existing adapters stay `BaseEngineForceAdapter` conformant) and
  add `native_closure_frame(q) -> (R, point)`, the frame and reference point of
  the native rows, which the NSX-02 converter needs alongside the grip frame
  returned by `closure_wrench_frame(q)`, and `closure_topology() -> LoopTopology`.
- Pinocchio drift: constrained dynamics solves `J a0 + gamma = 0` with no
  Baumgarte term, so `Jdot v = gamma = -J a0` at zero effort. It equals the
  finite difference of `J(q + t v) v` (tests at `1e-7` scaled) on and off the
  closure tangent space.
- For Pinocchio the grip frame is the hand-side weld frame (the native LOCAL
  frame), so the canonical conversion is the identity there; the converter is
  still applied, and the allocator is tested against fixtures served in other
  native conventions.
- `club_inertia_split` returns `SpatialInertia` values in the club-side
  closure frame (body-fixed; it coincides with the grip frame on a closed
  loop). `loop_support_indices` are the coordinates on the tree path between
  the two constrained joints.
- `verify_acceleration_parity` has one semantics: it takes applied joint
  efforts only and compares the target with `constraintDynamics(q, v, tau)`.
  A target built with an inconsistent multiplier is flagged. Legacy adapters
  keep the raw-equation audit; `parity_effort` folds `J^T lambda` in for them
  only.
- Spatial fixture check: `test_snapshot_vs_spatial_fixture.py` drives the NSX-12
  Pinocchio model through the real adapter methods and compares `M`, `h`,
  `J_c` and `Jdot_v` at `1e-9` scaled; only the spec-driven club inertia split
  is supplied from the fixture.

## NSX-14 Admission (#12559)

```python
def admit(trajectory: Sequence[ClosedLoopSnapshot], *, gates: AdmissionGates,
          times: ArrayLike, plant: ClosurePlant | None = None,
          repair: Literal["none", "project_to_closure"] = "none",
          rebuild: Callable[[Array, Array, Array], ClosedLoopSnapshot] | None = None,
          ) -> AdmissionReport
```

`times` holds one time stamp per frame. `plant` supplies the position-level
residual `Phi(q)` (the `ClosurePlant` of `project_to_closure`); a snapshot
carries no position residual. Without a plant the gate rejects unless
`gates.require_position` is `False`, an explicit and recorded skip of the
position level. `rebuild(q, v, a)` re-creates a snapshot at a repaired state and
is required, together with `plant`, when `repair="project_to_closure"`.

Repair reuses `project_to_closure` on frames failing at the position or
velocity level, then projects the acceleration onto the tangent set of the
projected state, `a' = a - J_c^+ (J_c a + Jdot_v)`, and re-evaluates. Every
correction (`dq`, `dv`, `da` norms and the before and after states) is recorded.
A frame failing only at the acceleration level is never repaired.

`AdmissionReport` carries per-frame scaled `Phi`, `Phi_dot`, `Phi_ddot`
residuals, derivative method and noise floor, time-synchronisation result,
contact-mode consistency and a verdict `ADMITTED`, `REJECTED(reasons)` or
`REPAIRED(record)`. Preconditions: at least 3 frames, strictly increasing
time. Postcondition: `AdmittedTrajectory` is constructible only from an
`ADMITTED` or `REPAIRED` report. Residual scaling: position `Phi` by the
characteristic length, velocity by length over time, acceleration by length
over time squared. Default gate: scaled residual below `1e-6` at each level. The characteristic
scales default to `L = 1 m` and `T = 1 s` (`length_scale_m`, `time_scale_s`);
callers should pass model scales.
Failing frames are named by index.

## NSX-15 Decomposition (#12560)

```python
def decompose(snapshot, *, weights: AllocationMetric) -> Decomposition
def zero_side_solve(snapshot, side: Literal["lead", "trail", "club_joint"]) -> ZeroSideResult
def min_metric_torque(snapshot, W: np.ndarray | AllocationMetric) -> np.ndarray
```

- `decompose` reuses `ForceNullSpace.from_balance` on the column-scaled
  `A = [S^T J_c^T (J_g^T)]`. Result fields: `x_p`, `N`, `rank_A`, `nullity`,
  `multiplier_gauge = m - rank J_c`,
  `attainable_torque_variation = rank J_c^T - rank J_{c,u}^T` (with `J_g`
  folded in as in the specification when present), scaled singular values and
  condition number.
- `zero_side_solve` returns `CONSISTENT_UNIQUE`,
  `CONSISTENT_NONUNIQUE(nullity)` or `INCONSISTENT(residual_scaled)`; the
  residual is `|| (I - J_s^T (J_s^T)^+) tau_ID,s ||`. Damping is recorded and
  never silently applied to an inconsistent system.
- `min_metric_torque` returns `tau = W^-1 S J_c^T lambda`-form minimiser of
  `tau^T W tau` subject to the equality; `W = M^-1` is allowed only as the
  labelled metric `C-METRIC-MINV`.
- Implementation notes (`loop_nullspace/decomposition.py`): `AllocationMetric`
  is a labelled SPD matrix on the actuated torques (`identity`, `inverse_mass`
  for `C-METRIC-MINV`; a bare matrix is recorded as `USER_DECLARED`). `x_p` is
  the minimum-metric-torque particular solution, with minimum scaled norm among
  those. `zero_side_solve` resolves the side from coordinate-name prefixes
  (`lead` and `club`; `trail`; `club`) unless `indices=` is given, reports the
  residual in physical (`residual`) and characteristic (`residual_scaled`)
  units, and records `damping`. `dimension_accounting` gives the counts without
  requiring a balanced state; `decompose` raises `BalanceInconsistentError`
  (a `ValueError`) when the unactuated rows cannot be balanced.
  `decompose_trajectory`, `zero_side_trajectory` and
  `min_metric_torque_trajectory` accept only an `AdmittedTrajectory` (NSX-14).
- Goldens: all four planar variants (`dimensions`, `zero_side`,
  `min_metric_torque`). Dimension identity
  `nullity = multiplier_gauge + attainable_torque_variation` holds when
  `n_g = 0`.
- Equivalence: `constraintDynamics(tau_p + N z)` reproduces `a` to `1e-9`
  scaled for random `z`.

## NSX-21 Feasible Set (#12564)

`FeasibleSet.from_hypotheses(decomposition, hypothesis_set)`. Rows carry the
hypothesis id. `conflict_set()` returns an inclusion-minimal set of ids
(IIS); golden `envelope_analytic_lp.infeasible` names the expected minimal
set. Circular cones: declared facet count `k` and error bound
`1/cos(pi/k) - 1` for the outer polygon (inner polygon scale `cos(pi/k)`).

Implementation (`feasible_set.py`, `feasible_rows.py`): `x = x_p + N z` with
`x = (tau, lambda, f_g)`; rows are `g . z <= h` with labels
`<hypothesis id>:<item>:<side>` and the declaring hypothesis id. Torque rows
use the `CapacityVector` (actuated order must match the decomposition). Each
`FrictionCone` (indices into `x`) gives a unilateral normal row, `k` linear
facets (outer or inner, declared `k` and bound `1/cos(pi/k) - 1` or
`1 - cos(pi/k)`) and one exact SOC block `(mu n, t1, t2)`. A hand squeeze
floor is `selector . x + offset >= minimum` (sign convention of NSX-16: `s1`
negative is squeeze). `is_empty()` and the conflict queries use the exact
cones; `to_lp()` uses the linearisation; `to_socp()` uses the exact cones.
`conflict_set()` is minimal at hypothesis level (deletion filter);
`conflict_rows()` is a row-level IIS (elastic filter, then deletion filter).
Rows resting on an ASSUMED capacity slot or on a hypothesis that fails the
display gate carry flags (`flagged_rows()`, `rests_on_unverified`). Cone
data is accepted only when `H-FRICTION-CONE` is declared, likewise for grip.

## NSX-22 Static Envelopes (#12565)

`static_envelopes(feasible_sets, quantities) -> EnvelopeSeries`. Golden
`envelope_analytic_lp.static` gives bounds, Chebyshev centre and radius, and
sign classes; the trajectory-coupled case and unbounded cases are separate
keys. Unbounded bound is NaN with status `UNBOUNDED`. Cold and warm solves
return the same bounds to `1e-9`.

Implementation notes (`loop_nullspace/envelopes.py`, #12565):

- A quantity is an affine functional `q(z) = const + coeff . z` of the null-space
  coordinates (`EnvelopeQuantity`); `joint_torque_quantities()` and
  `x_functional_quantities(...)` (hand-split coordinates are rows of `Phi`
  composed with the closing-hand map) build them per frame from the set's
  decomposition. Each frame is one `LPSession`: a zero-cost solve decides
  feasibility (`INFEASIBLE` is reported, never raised), then two objective swaps
  per quantity reuse the basis, and the basis carries to the next frame when the
  dimensions match. `warm_start=False` resets before every solve; bounds agree
  to `1e-9`.
- Sign tolerance: `atol = SIGN_ATOL_RTOL * scale`, `SIGN_ATOL_RTOL = 1e-9` (the
  NSX-00 scaled balance threshold), `scale` the quantity's characteristic scale
  (`M_c = 5 N m` for torques, `F_c = 100 N` for forces). `ZERO` when both bounds
  lie within `atol` of 0, `POSITIVE` when `lower > atol`, `NEGATIVE` when
  `upper < -atol`, else `INDETERMINATE`; a one-sided unbounded bound can still
  decide a sign. An infeasible frame has no sign class (`None`).
- Chebyshev margin: largest ball `{z : z^T W z <= r^2}` with diagonal `W`
  (golden `weighted_diag_1_4` uses `W = diag(1, 4)`, row norm
  `sqrt(g W^-1 g)`); `UNBOUNDED` (NaN) when balls of any size fit, radius `0`
  when the set has no interior.

## NSX-23 Trajectory Allocation (#12566, Strong)

`allocate_trajectory(feasible_sets, objective, *, reference=None)`. Golden
`c_pm_identity`: with uniform `c_plus`, `c_minus` the cost is
`1/2 (c_plus + c_minus) sum|p| + 1/2 (c_plus - c_minus) P_net` and `P_net` is
constant on `J_c v = 0`; the uniform-weight minimiser is unique and equal for
all `c_minus / c_plus`; heterogeneous weights give a different minimiser.
Curvature (golden `planar_*.curvature`): the retained-space Gram matrix
eigenvalues are positive.

Implemented in `loop_nullspace/allocation.py` (types in `allocation_spec.py`):

- Unknown `w = (z_1..z_T, s)`; torques are affine, `tau = T0 + Ntil z`. Each
  quadratic term is `|A tau - a|^2` with `S = diag(torque_scale)` (convention
  `C-METRIC-CAPACITY`): effort `a_e sum w_k |S^-1 tau_k|^2`, rate
  `a_r sum |S^-1 dtau|^2 / dt_k`, reference `a_ref sum w_k |S^-1 (tau - ref)|^2`
  (`w_k` trapezoid weights over `times_s`). The gross-power epigraph
  `s >= c+ p`, `s >= -c- p` with `p = v tau` is piecewise linear.
- Strict convexity is checked at build time on the retained space (the
  z-directions that change a torque): the quadratic Gram matrix must have rank
  equal to `sum_k rank N_a,k`. Torque-invisible directions (multiplier / `f_g`
  gauge) are reported as `gauge_dimension`, not penalised; the optimal torque
  is unique, the gauge coordinates are not. A failure raises
  `NotStrictlyConvexError` naming the missing term(s) (effort or reference).
- Reduction report: `ABS_POWER_ONLY` (`c+ = c-` per joint), `UNIFORM_NET_PLUS_ABS`
  (uniform weights and `v^T dtau/dz = 0`, so `c-/c+` is a dead parameter at fixed
  mean), `NONE` (heterogeneous). The reduced `1/2 (c+ + c-) |p|` form is used
  when detected (`allow_reduction=False` forces the unreduced epigraph).
- Result: `QuantityRecord(FAMILY_DEPENDENT)` with every hypothesis (feasible-set
  ids plus `H-EFFORT-CAPACITY`, `H-SMOOTH-TORQUE-RATE`, `H-GROSS-POWER-COST`
  when active), row and cone duals, Clarabel KKT residuals (scaled), solve time.
  Exact cones are used; linearised cone rows are ignored. The reference-tracking
  term has no registry hypothesis; it is flagged by `reference_used`.
- Solver: `solve_socp` gained an optional quadratic term `P` (objective
  `1/2 x'Px + c'x`, stationarity residual includes `Px`) and `tol`; the
  `P=None` behaviour is unchanged.
- Anthro acceptance is blocked on `J_g` (NSX-60): see the NSX-22 blocker above.
  `tests/integration/test_loop_nullspace_anthro_allocation.py` skips with that
  reason; the planar-oracle benchmark in `tests/unit/loop_nullspace/test_allocation.py`
  records solve time and KKT residuals meanwhile.
- Non-claims: the optimum is a hypothesis-conditioned representative, not an
  estimate of true hand loads; no "zero sign flips" criterion is used.
  `force_nullspace/redistribution.py` is untouched (API-compatible); its shim
  onto this core is NSX-24.

## NSX-25 Pareto and Probes (#12568)

```python
def pareto_front(feasible_sets, objectives, eps_grid, *, references=(None, None)) -> ParetoFront
def certify(feasible_sets, predicate, window=None, *, coupling=(), aggregation="ALL") -> Certificate
def verify_certificate(cert, feasible_sets, *, coupling=(), predicate=None) -> VerificationReport
def trajectory_envelope(feasible_sets, quantities, *, coupling=()) -> TrajectoryEnvelope
```

Modules: `probes.py` (public API, re-exports), `probe_certificates.py`
(leaf certificates, numpy verifier), `trajectory_system.py` (stacked set, solver
adapter), `trajectory_envelope.py`, `pareto.py`.

**Predicates.** `AffinePredicate(quantity, sense, threshold)` with
`sense in {ge, le}` normalises to `f(z) = s (const + coeff . z) >= s theta`.
Only affine functionals exist: the constructor accepts an `EnvelopeQuantity`,
a sequence of them or a quantity factory; `AffinePredicate.from_function`
evaluates a callable at the origin and the unit vectors and tests the fit at
random points, raising `NonAffinePredicateError` (a `ValueError`) otherwise.
Non-convex predicates are out of scope.

**Trajectory-coupled set.** The frames' sets are stacked in
`z = (z_1, ..., z_T)` and intersected with hard rate bounds
`|q_{k+1} - q_k| <= delta_k` on an affine quantity (`RateBound`, the
`trajectory_coupled` oracle; hypothesis id `H-SMOOTH-TORQUE-RATE`). The
coupled set is a subset of the static one. `certify` keeps Coulomb cones as
exact second-order-cone blocks, so neither verdict depends on the declared
polygon; `trajectory_envelope` uses the declared linearisation like the static
envelopes.

**What "certified" means (strongest standard notion, no new math).** For a
normalised functional `f` and the stacked system `A z <= b` (polyhedral rows
`G z <= h` plus cone blocks `b_j - A_j z in SOC`), a leaf carries

* `LOWER_BOUND`: a primal witness `w` (feasible, value `f(w)`) and a dual `d`
  with `d >= 0` on rows, `d_j in SOC` on cone blocks (self-dual) and
  stationarity `c + A^T d = 0`. Weak duality gives `f(z) >= const - b . d` for
  every feasible `z`; the witness gives `min f <= f(w)`. This is primal
  feasibility plus a zero-duality-gap certificate checked by the verifier, not
  a trust in the solver status.
* `FARKAS`: `d` in the dual cone, `A^T d = 0`, `b . d < 0` (set empty).
* `WITNESS_ONLY`: `f` is unbounded below; a feasible witness with `f` below
  the threshold (found with the violation as an extra row) proves failure.

Verdict, with `atol = SIGN_ATOL_RTOL * scale` (the NSX-22 sign tolerance, never
a bare 0): `HOLDS` iff certified bound `> theta + atol`; `FAILS` iff a feasible
witness has `f < theta - atol`; otherwise `UNDECIDED("BOUNDARY")` (optimum
within `atol` of the threshold, consistent with "a bound that touches zero is
INDETERMINATE"). An empty set gives `UNDECIDED("EMPTY_FEASIBLE_SET")` with its
Farkas leaf, never a vacuous HOLDS. A leaf the verifier rejects is downgraded
to `UNDECIDED("CERTIFICATE_REJECTED: ...")`. `aggregation="ALL"` asks the
predicate of every window frame (one LP each, one persistent model);
`"SUM"` asks it of `sum_k q_k` (one LP).

`verify_certificate` rebuilds the stacked system from the sets, checks that its
SHA-256 digest equals the certificate's, re-checks every leaf with numpy only
(`verify_leaf`) and, if given the predicate, that the leaf functionals are its
own. Tolerances: stationarity, cone membership and stored values to `1e-8`
scaled; witness row violation to `1e-7` scaled (the HiGHS feasibility default).
The certificate is therefore exact up to the reported residuals, not a
rational-arithmetic proof. `Certificate.to_json` / `from_json` round-trip every
array and number exactly (shortest round-trip float text).

**Pareto.** `objectives = (J_a, J_b)` are two `ObjectiveSpec`s over the same
frames (each objective is the sum of the quadratic terms its spec enables;
`J_a` may include gross power, `J_b` may not). The solve is
`min J_a(z) s.t. J_b(z) <= eps`, with `J_b = |M z + m|^2` imposed exactly as the
cone `(sqrt(eps), M z + m) in SOC`; `J_a` must be strictly convex on the
retained torque space (NSX-23), so each OPTIMAL point is unique and Pareto
optimal in the torque objectives. The cone multiplier gives the slope
`d J_a / d eps`. Oracle: two frames, one torque, closed form in
`tests/unit/loop_nullspace/test_pareto.py`. An `eps` below the attainable
`J_b` is reported `INFEASIBLE`. Every point is `FAMILY_DEPENDENT` and lists all
hypotheses of both objectives. `explore_torque_tradeoffs` keeps its return
shape and now emits a `FutureWarning` naming it a weight sweep.

Goldens: `envelope_analytic_lp` (`trajectory_coupled`, `infeasible`,
`unbounded`, `static`).

## NSX-26 Reaction Restriction (#12569)

`restrict(snapshot, kind) -> ClosedLoopSnapshot`. Admissible restrictions are
the nesting `WELD6 -> SHAFT_FREE5 -> BALL3` by row selection in the grip frame:
SHAFT_FREE5 drops the twist moment about the shaft axis `u` (row `tx`); BALL3
keeps the three force rows. The set of admissible reactions for the restricted
kind is a subset of the WELD6 set, so envelopes of the restricted kinds are
contained in the WELD6 envelope for the same fixed welded trajectory (note the
direction: restricting reactions shrinks the feasible set). Output label
`REACTION_RESTRICTION_SENSITIVITY`.

## NSX-30 Constrained Counterfactuals (#12570)

```python
def constrained_acceleration(M, h, tau, J_c, Jdot_v, *, baumgarte=None) -> tuple[np.ndarray, np.ndarray]  # (qdd, lambda)
```

KKT projector `M^-1 (I - J_c^T Lambda_c J_c M^-1)` with
`Lambda_c = (J_c M^-1 J_c^T)^-1`. Postconditions: `J_c qdd + Jdot_v = 0` to
`1e-9` scaled; the total control-induced acceleration is independent of the
chosen `lambda` family. Planar goldens provide `M`, `h`, `J_c`, `Jdot_v`.

Implementation (NSX-30): `loop_nullspace/constrained_dynamics.py` holds the single
projector (`constrained_acceleration`, `kkt_projector`, declared `Baumgarte`
terms, `closure_acceleration_residual`); `tau` is the generalised load
`S^T tau_a`. The pendulum solver calls it with
`singular_mass_fallback=True` because its massless club coordinate makes `M`
only semi-definite; the fallback solves the equivalent augmented block system
and is an error without the flag. `simulation_backends.protocol` adds
`ConstrainedEquationsOfMotionProvider` (`closure_jacobian`, `closure_drift`);
`ztcf_acceleration`, `zvcf_acceleration`, `drift_and_control_split` and
`zero_velocity_control_preserved_acceleration` dispatch to the projector for such a
provider. `constrained_counterfactual_report` returns ZTCF, ZVCF, the control
total (`INVARIANT`) and the per-actuator split (`FAMILY_DEPENDENT`).
`loop_nullspace.provider.AdapterConstrainedProvider` exposes any `FULL`
NSX-13 adapter as such a provider. `create_counterfactual_rollout` requires
`dynamics=CounterfactualDynamics(provider, nullspace=...)`, integrates the
provider with RK4 (load held per step), and `NULLSPACE_EXPLORATION` samples `z`
through `NullspaceExploration` (NSX-15 decompositions); the `m_eff = 1.0` mock
and the `5 sin(t)` placeholder are removed.
Without an explicit `dynamics`, `motion_matching/counterfactual_provider.py`
builds the provider from the session's own model specification (Pinocchio
adapter, `AdapterConstrainedProvider`, re-expressed in the session coordinate
order by `ReorderedProvider`) and caches it by `model_sha256`. A specification
missing `bodies`/`joints`/`coordinate_order`, with a mismatched coordinate
order, or without a `closure` fails closed with a `ValueError` naming the
input, which the route returns as 400; the Pinocchio model needs a closure,
so no unconstrained provider is built from a specification. Achieved evidence
on the 41-coordinate anthro model against raw `constraintDynamics`: ZTCF
8.4e-12 and ZVCF 3.9e-13 scaled; ZTCF + control total under a random actuated
load (reference magnitude 9.5e3) 2.5e-12 scaled.
`ztcf_zvcf` keeps its naming: ZTCF removes the control torque, ZVCF sets
`v = 0` and `u = 0`; on a loop both use the projector with the reaction
re-solved, never a held `lambda`.

## NSX-31 Replay (#12571)

`replay(allocation, provider, *, policy, setup, feedback=None, settings=None)
-> ReplayReport` (`loop_nullspace/replay.py`; inputs in `replay_spec.py`,
ground loads in `replay_ground.py`). It integrates the constrained dynamics
forward from the first state only, under the allocated torques, and compares
the result with the reference trajectory. It reuses the NSX-30 KKT projector
(`constrained_acceleration`, with the reaction re-solved at every RK4 stage) and
the counterfactual RK4 (`rk4_step_with_load`, the generalisation of the
existing `_rk4_step` to a time- and state-dependent load). There is no second
integrator or projector.

### Modes and the Mandatory Label

| `ReplayPolicy`           | `ReplayMode` | `evidence_label`                | What it is                                                            |
| ------------------------ | ------------ | ------------------------------- | --------------------------------------------------------------------- |
| `INDEPENDENT_TIME_ONLY`  | `OPEN_LOOP`  | `independent_open_loop_replay`  | Allocated torque applied as is; only time enters.                     |
| `STATE_FEEDBACK`         | `FEEDBACK`   | `feedback_assisted_tracking`    | Allocated torque plus a declared feedback law on the state error.     |

`ReplayReport.__post_init__` refuses a mode that disagrees with its policy, an
open-loop report that carries any feedback, a feedback report without its law,
series and budget, and any state reset. `may_present_as_validation` is always
`False`: a feedback-assisted replay is tracking, never validation, and a UI may
not show it as the latter. The report also carries `NON_CLAIM`.

### Equations

With `S` the actuation selection (coordinate rows), `tau_a(t)` the allocated
torque interpolated from the allocation nodes (`zoh`, `linear` or `cubic`
spline: orders 1, 2 and about 4), `g(t, q) = J_g(q)^T f_g(t)` the known external
ground load and `(a, lambda) = KKT(M, h, S^T tau + g, J_c, Jdot v)`:

- open loop: `tau = tau_a(t)`;
- feedback: `tau = tau_a(t) + tau_fb`, `tau_fb = F(q_ref - q, v_ref - v, q)`.

`tau_fb` is stored as its own series and never added into `allocated_torque`.
Its budget is relative to the allocated series: `peak_norm_ratio = max_t
|tau_fb| / max_t |tau_a|`, `energy_ratio = int |tau_fb|^2 dt / int |tau_a|^2
dt`, `rms_ratio`, absolute mechanical work `int sum_i |tau_i v_i| dt` of each
series, the per-joint RMS, and the fraction of saturated samples (trapezoid
integrals). A zero allocation with non-zero feedback has ratio `inf`, never
`nan`.

Closure drift is reported in both modes: velocity `J_c v` always, position
`Phi(q)` only when the provider exposes `closure_error` (otherwise `None`, not
zero). Any Baumgarte stabilisation (`ReplaySettings.baumgarte`, gains
`alpha`, `beta`) is declared in the report together with the peak
acceleration it added, `stabilisation_acceleration_peak`, and is reported apart
from the physics; the default is none.

Time to divergence is the first replay node at which `max_i |q_i - q_ref,i|`
exceeds `divergence_tolerance` (radians or metres per coordinate; 0.05 for the
anthro runs). A run that blows up (non-finite state, a state above `1e8`, or a
KKT failure) stops there and says so in `terminated_reason`.

### Declared Feedback Laws

`FeedbackLaw(kp, kd)` is a per-joint or symmetric PSD joint-space PD law.
`AccelerationFeedbackLaw` is the state-dependent acceleration-space PD used for
the anthro runs: `tau_fb = pinv(R(q)) (omega^2 e + 2 zeta omega e_dot)` with
`R(q) = S P_c(q) S^T` the actuated acceleration response of the closed loop at
the current configuration and `zeta = 1`. It is scale-free across joints
whose inertia spans `1e-6` to `1e0` kg m^2 and removes directions the loop makes
uncontrollable (`rcond = 1e-6`). Only the 35 actuated coordinates get feedback;
the six root coordinates are unactuated.

### Window Rule (Anthro Fixture)

Frames `0, 3, ..., 597` of the ground-supported anthro record are the NSX-22
benchmark set, 199 frames of which 124 have a non-empty free feasible set under
the ASSUMED capacity prior (75 are INFEASIBLE, as already recorded). The replay
window is the longest run of adjacent (3 record steps apart) usable frames,
earliest on ties. It is chosen by that rule alone, not by outcome: runs are
(frames, count) 0 to 90 (31), **96 to 339 (82)**, 345 to 348 (2), 534 to 537
(2), 543 (1), 549 to 564 (6). The window is record frames 96 to 339, `t =
0.288` to `1.017 s`, 0.729 s long. The initial state is the closure-projected
measured state of frame 96. The allocation (NSX-23, `rate_weight = 0.1`) is
OPTIMAL with KKT residuals primal 2.6e-14, dual 5.7e-10, complementarity 2.2e-13.

Ground loads: the allocated `f_g` is applied as a known external load
`J_g(q)^T f_g` at the replayed configuration on the contact set of the
allocation frame. It is an input, not feedback, and not contact dynamics: no
contact is released or made.

Load-map check (so a divergence is dynamics, not plumbing): at the measured
states, the allocated loads reproduce the measured accelerations to 2.5e-7
(1.8e-9 relative to the peak acceleration).

### Results on the Anthro Window

Open loop (`INDEPENDENT_TIME_ONLY`, RK4 3 sub-steps per 9 ms, linear
interpolation):

- Diverges early: time to divergence **21 ms** (tolerance 0.05); the error is
  0.013 at 10 ms, 0.10 at 30 ms, 0.63 at 50 ms, 8.8 at 100 ms, and the run
  blows up (state above `1e8`) at `t = 0.45 s`. Early log-linear growth rate
  about 105 per second (6 to 30 ms): this is a hard-unstable open loop, not
  noise. Worst coordinates at 50 ms: `mtp_angle_r` 0.68, `mtp_angle_l` 0.41,
  `subtalar_angle_l` 0.24 rad.
- Integrator check: 6 sub-steps give the same 21 ms and the same early errors
  (0.0127 at 10 ms, 0.103 at 30 ms). `zoh` diverges at 12 ms, `cubic` at 21 ms.
  Interpolation changes the amplitude, not the verdict.
- Closure drift stays tiny until divergence (velocity 7.4e-7, position 1.2e-8)
  and is huge only in the blow-up tail (max 1.3 velocity, 1.4e-3 position); do
  not read the tail maxima as a closure statement.

Feedback-assisted (`STATE_FEEDBACK`, acceleration PD, `zeta = 1`). `omega` is the
natural frequency of the declared law; `capacity` is the ASSUMED torque
capacity prior.

| `omega` [rad/s] | sub-steps | time to divergence | max state error | peak ratio | energy ratio | abs-work ratio | peak / capacity | joints over capacity |
| --------------- | --------- | ------------------ | --------------- | ---------- | ------------ | -------------- | --------------- | -------------------- |
| 50              | 3         | 36 ms              | 4.1             | 1.93       | 1.65         | 1.17           | 8.8             | 20                   |
| 100             | 6         | 135 ms             | 2.9             | 1.63       | 0.99         | 1.18           | 6.5             | 19                   |
| 150             | 6         | none               | 0.048           | 0.196      | 0.0076       | 0.12           | 1.24            | 1                    |
| 300             | 12        | none               | 0.047           | 0.229      | 0.0086       | 0.13           | 1.55            | 1                    |

Reading it honestly: the allocated torques alone do not reproduce the motion
beyond about 21 ms. Tracking the whole 0.729 s window needs feedback at
`omega >= 150`; at 150 the feedback has 0.76 percent of the allocated energy,
12 percent of its absolute work and a peak 20 percent of the allocated peak,
but its peak is 1.24 times the ASSUMED capacity on `RFInput`, one joint, and
1.55 times at `omega = 300`. At `omega = 50` and `100` the law does not hold the
state, so their ratios describe the feedback fighting a diverged state and are
not a budget; do not quote them as one. The numbers hold for this law, window,
capacity prior and tolerance only.

### Oracle Evidence (Planar Golfer)

The reference is DOP853 at `rtol = 1e-13` with dense output (no inverse crime).
Exact-torque open-loop replay reproduces it within integrator error; RK4 with a
held load is fourth order; interpolation orders are 1, 2 and about 4; feedback is
negligible when tracking is exact (peak under 1e-4 of allocated, energy under
1e-9); a zero-gain law equals the open loop; the feedback budget grows with an
injected parameter mismatch; and a real NSX-23 allocation (a different family
member from the driving torque, differing by more than 1 N m) replays to the
same trajectory (error 5.6e-6).

### Failed Experiments

- Fixed per-joint PD gains (`kp = 300`, `kd = 30`) were unstable under explicit
  RK4 on the oracle (the state exploded within 10 nodes); the oracle test uses
  `kp = 40`, `kd = 1.5`.
- On the anthro chain, diagonal PD and a frozen-`Lambda` matrix PD both blew up:
  inertias span six orders of magnitude and the closure couples them. This is
  why the state-dependent `AccelerationFeedbackLaw` is the declared law.
- A stride-1 allocation of the same window returned `NUMERICAL` with
  `rate_weight = 0.1`; the stride-3 window above is the reported one.

### Limitations and Non-Claims

- Inverse kinematics, feedback-assisted tracking and independently replayed
  open-loop dynamics are different things. Only the open-loop mode is an
  independent replay, and even it shows only that this allocation, with this
  model, does or does not hold; it does not validate or refute the torques.
- The ground load is an applied input. A diverged replay keeps pushing at the
  allocated force through contacts that may have moved.
- The feedback law is one declared choice. Another law gives another budget.
- Capacity, friction and grip hypotheses remain ASSUMED; foot and head
  observability limits are unchanged.
- Software correctness only. Scientific qualification stays in the
  design-manual governance pathway; a successful run is not acceptance.

## NSX-60 Lower-Body Loop (#12585, Strong)

Two-foot ground contact is a second unilateral null space: with rigid contacts
the balance is `A x = b`, `A = [S^T J_c^T J_g^T]`, `x = (tau, lambda, f_g)`.
Golden `spatial_counts` variants `floating_root_two_point_feet` and
`floating_root_four_point_feet` fix the counts (two point feet: contact-map
rank 5, nullity 7, gauge 1; four point feet: nullity 12). Golden
`lower_body_observation` (sympy, exact, no repository code) gives
`rank(E_x N)` for five observation maps, and the numeric fixture at zero root
pose (`zero_root_pose=True`) reproduces every entry.

| Observation map | 2 points | 4 points |
|---|---|---|
| Net force and moment (root rows already fix it) | 0 | 0 |
| Net force | 0 | 0 |
| Vertical load of each foot | 0 | 1 |
| Force of each foot | 1 | 3 |
| Every point force | 1 | 6 |

Implementation (`loop_nullspace/ground_contact.py`, `ground_envelopes.py`):

- Seam: `PinocchioForceAdapter.foot_contact_candidates(q)` returns the six

  foot_contact_tol_m=T)` keeps candidates with `gap <= T` and stacks their rows
  of `compute_contact_jacobian` as `J_g`; without `T` (default) `J_g` stays
  `None` and no other engine changes. An adapter without the method raises
  `CapabilityUnavailable`.
- Cones: `foot_friction_cones(snapshot)` builds one `ContactCone` per contact over

## NSX-93 Declared Impedance and Delayed Feedback Layer (#12722)

Modules (all under `src/shared/python/loop_nullspace/`):

- `impedance_spec.py`: `JointImpedance` of `ImpedanceWindow`s,
  `H-DECLARED-JOINT-IMPEDANCE`. Each window is a symmetric PSD stiffness `K`
  [N m/rad] and damping `D` [N m s/rad] over `[t_start, t_end]` with a
  raised-cosine ramp; off-diagonal entries are biarticular coupling;
  overlapping windows add. `noise_scale = 1 + kappa_i K_ii(t)` is the declared
  noise-inflation penalty (`kappa` is an input with no source, a declared
  hypothesis). The impedance is declared, never inferred from net torque (V5).
- `feedback_runtime.py` and `feedback_layer.py`: `FeedbackLayer` is a
  run-scoped feedback law that `replay()` starts per run through
  `begin_run`. The impedance acts on the current error `K e + D de`; the
  `GainSchedule` feedback acts on the delayed error (`DelayedFeedback`,
  whole-step delay, Hermite history, initial state held before the start;
  `0 < delay < max_step` is rejected). The replay reports the layer's torque on
  the feedback line, separate from the allocated torque (R10).
- `minimum_intervention.py`: `minimum_intervention_design` is TVLQR with
  `Q = 0` and terminal weight `C_imp^T W_y C_imp` (`face_only_weights` for the
  face-only case). The gain annihilates `ker(W^(1/2) C Phi)`, so it corrects
  only outcome-relevant deviations; `task_irrelevant_gain_norm` reports the
  residual (1e-15 observed, tested to 1e-10). `joint_space_gains` maps the
  tangent gain to joint coordinates with `Kq = (K_xi - K_eta P^T O) P^T`,
  `Kv = K_eta P^T`; `tangent_velocity_offset` (NSX-84) supplies `(P, O)`.
- `layer_linear.py`: `LayerLinearization` folds the impedance into the
  continuous closed-loop `F - G_u K_imp` before the (zero-order-hold) matrix
  exponential and appends `m` delayed copies of the state for the feedback;
  `layer_variance` reuses NSX-90 `assess_variance` unchanged and puts the
  layer hypotheses on the `conditioning` axis (NSX-81). `frozen_delay_margin`
  and `LayerLinearization.delay_margins` give the first destabilising delay.
  `variance_ratio_record` is `UNAVAILABLE` (reason: co-contraction is not
  identifiable from net torque) unless the impedance is declared.
- `layer_accounting.py`: `account_layer` splits a replay into the allocated,
  impedance, feedback and total lines. Each carries its `FeedbackBudget`
  (peak, energy and absolute-work ratios), an `EffortCost` (`int tau^2 dt`,
  positive and negative joint work) and, for the impedance, the dissipated and
  peak elastic energy. Effort is bookkeeping of the declared model, not a
  physiological cost.
- `replay_campaign.py`: `TorqueNoise.scale` `(n_steps, n_channels)` multiplies
  the draw interval by interval (the noise-inflation penalty); `None` and ones
  are the same trial exactly.

Equations and frames. Tangent state `x = (xi, eta)`, `dq = P xi`,
`dv = P eta + O xi`. Actuated errors `e = S P xi`, `de = S P eta + S O xi`.
Impedance `K_imp = K S P + D S O` (position block), `D S P` (velocity block);
`u = -K_imp dx`. Delayed feedback `u_t = -K_fb,t dx_(t-m)` with
`z_t = (x_t, ..., x_(t-m))`, `P0_aug = T P0 T^T`, `T = [I; ...; I]`. Units: N m,
rad, s; outcomes in the units of their rows.

Tolerances (derived, none tuned). The oscillator oracle `var = S/(2 d k)`
differs from held noise by a sinc factor of order `(omega_n dt)^2 / 12`, so the
test tolerance is `(10 dt)^2 / 6`. The PD delay margin on a double integrator is
`tau_c = atan(kd w_c / kp) / w_c` with `w_c^2 = (a + sqrt(a^2 + 4 b)) / 2`,
`a = (kd/m)^2`, `b = (kp/m)^2`; the discrete margin is tested to +-1.5 dt and
the replay is stable at 0.7 and unstable at 1.3 times it. The Monte Carlo
cross-check uses the SD sampling half-width `Z99 / sqrt(2 (N - 1))` of NSX-91.
The zero-layer negative control is exact (`assert_array_equal`) in replay and
`rtol 1e-13` in the linear chain.

Failed or revised experiments. A threshold of 0.01 times the open-loop variance
for a stiff joint failed (ratio 0.15) and was replaced by the analytic base
variance; the first stationary-variance tolerance was loosened to the observed
`-(omega_n dt)^2/12` bias and then tightened to the derived bound; a Monte
Carlo of the delay margin over 100 steps was too slow (eigenvalues of a
`202`-square companion per step), so the default search is 20 steps.

Reproduce:
`python3 -m pytest tests/unit/loop_nullspace/test_impedance_spec.py
test_feedback_layer.py test_minimum_intervention.py test_layer_linear.py
test_layer_nonlinear.py test_layer_seam.py test_layer_accounting.py -n 0
-o addopts=""`.

Non-claims. Impedance, noise inflation and delay are declared hypotheses; no
stiffness is inferred from net torque and no co-contraction effect is claimed
without the declaration (`UNAVAILABLE`). Burdet 2001 supports selective control
of impedance geometry, not co-contraction. The feedback is uncompensated delayed
state feedback (no predictor). The frozen delay margin is a first-loss
diagnostic, not a time-varying stability proof. The tangent chain is `k = 1`
(NSX-84). `H-TIMING-JITTER` is not implemented here. Engine coverage is the
analytic point mass, pendulum and planar-golfer oracles through the provider
seam, not every engine adapter.

A not-implemented or unavailable arm returns its reason and no numbers; the
campaign lists it under `not_attempted` and excludes it from the failure rate.

Declared choices (ambiguities resolved conservatively).

- One mechanism at a time. S1 keeps the signal-dependent noise (M1) and freezes
  the geometric preload at the nominal motion; S5 keeps the preload (M2) with
  additive noise. Effects are attributable and not additive when both channels
  act (that combined arm is the NSX-92 problem itself).
- Ranking basis. Arms are ordered by the face-angle variance ratio to the
  strategy-off baseline of their own representation; S8 cases use the reference
  case's baseline. Absolute variances are reported but not compared across
  representations. An arm whose ratio is not below one cannot win.
- Matched CHS. Clubhead speed is an input of each case. An arm outside
  `chs_rel_tol` of the reference (slower *or* faster, or of unknown speed) is
  excluded with `SPEED_MISMATCH`; the speed-for-consistency trade belongs to the
  unconstrained fronts. Matched effort adds a common cap *within one effort
  basis* (allocated torque, expected layer torque, muscle activation are separate
  lines, R10); an arm over the cap is excluded, never relaxed.
- Negative controls. A flat NSX-92 objective, a zero impedance, a zero feedback
  gain, a missing preload for S5 or a curve with no declared mechanism returns
  `NO_MECHANISM` with ratio exactly one and effect zero.
- Co-contraction baseline is the lowest level of the NSX-94 sweep (the least
  co-contraction that still produces the net torque), not zero co-contraction.
- Delay verdict. A feedback arm is `UNSTABLE` (a failure) when the frozen delay
  margin of any step is at or below the declared delay.
- Expected layer effort is `sum_t dt tr(G_t P_t G_t^T)` of the declared torque
  `u = -G z`; it is an accounting of the declared model, not a physiological cost.
- Priors are whole contexts. A reversal is a pair strictly ordered one way in one
  prior and the other way in another. Hold-out status is `CONFIRMED` only when the
  hold-out SD difference reproduces the order with an interval excluding zero,
  `REVERSED` when it contradicts it the same way, else `INCONCLUSIVE`.

Fixtures used in the tests (invented demonstrations, none a golfer measurement):
the NSX-92 pendulum for S1/S5/S8, the NSX-93 double integrator for S2/S3/S7 and
the NSX-94 antagonist pair for co-contraction. Observed results of those
fixtures are not claims about golfers; a late impedance window helped less than
full-horizon stiffness and needed *more* expected effort, because early
regulation keeps the feedback torque small.

Non-claims. Rankings are conditional on the declared priors, mechanisms and the
linear tangent model at the nominal motion; they compare mechanisms inside a
model, not golfers, and are not coaching advice until externally validated. The
ledger records software correctness only; scientific qualification stays in the
design-manual governance pathway.
