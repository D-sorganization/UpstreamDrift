# Standalone Caption Scope and Narrow Repair

A stable-file scan recorded in `caption_scope.json` finds the omission in all 52 social cell SVGs: 36 from 18 PW primary cells and 16 from eight control cells. Both density and overhead cards omit protocol and numeric target. Their academic companions identify source protocols. At this provisional snapshot, all 29 completed pair-social density SVGs also omit both identifiers. The producer is still adding files, so this is an exact snapshot count, not the final affected total.

For primary PW cards, the missing context is the within-lean nominal target and broadened face-search protocol. For control cards, it is the common fixed target and face-bound or speed-bound sensitivity protocol. For paired density cards, each ordered condition's source protocol and the shared target matter: a curve comparison can cross original and supplemental protocols, while across-lean comparisons specifically hold the target fixed. A plotted target cross alone does not communicate that design. Existing pair-overhead code already prints the numeric target and both source protocols; it is outside this omission finding.

The smallest rendering repair is to add actual source protocol, target-request mode (within-lean nominal or fixed target), and the saved target distance to cell social metadata, and add ordered source-protocol context plus the common target to `write_pair_social_density` through its existing metadata construction. Do not infer protocol from club/profile names or overwrite population/scale metadata. Use the actual saved target, not an independently recalculated value. Keep details wrapped below a short scenario heading. Tests should check actual primary/control/cross-protocol payloads, condition order, preserved counts/coordinates and actual rendered text bounds.

The current pipeline has no figure-only/resume CLI. `build_final_supplement_report` requires an empty output directory, calculates comparisons, and then renders. `load_verified_supplement_artifacts` supplies the existing authoritative verification boundary, but checks producer source hashes: changing the renderer and simply reusing that loader in the changed checkout would correctly fail. Do not weaken this check or relabel old numerical receipts as newly produced.

A saved-data figure-only revision is possible only with an explicit new publication path: verify the completed old package using its exact producer snapshot; retain its immutable receipt and numerical JSON/CSV hashes; use those source-bound records to render a fresh figure directory with a new renderer-source receipt; recheck source and numerical bytes afterward. This needs a narrow, tested publication entry point and explicit original-numerical versus new-renderer provenance. Existing private `_render_cell_figures` and `_render_pair_figures` already accept refs/pairs and should be reused, not duplicated. If this bounded revision contract is not implemented, a fresh normal saved-data pipeline run is the existing supported route. Neither route requires flight simulations. No regeneration or source change has been performed in this review.
