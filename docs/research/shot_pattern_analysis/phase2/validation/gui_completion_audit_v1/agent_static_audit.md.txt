## 1. Executive Summary

This audit assesses the completion of the phase-two **Matched Shot-Pattern Analysis** goal against all explicit user requirements:
- Integrated shot-pattern tile with Driver, 7-Iron, and Pitching Wedge
- Matched nominal physical landings without post-flight aiming
- Sourced static loft documentation
- Shaft lean variations at 0°, 5°, and 10°
- Shaft twist SD 1° and 2°
- Contact horizontal and vertical SD 0.25 inch
- Variable club speed SD 1 and 2 mph
- Variable club path SD 0.5°
- User-editable symmetric covariance matrix across all seven delivery noise variables with positive-semidefinite (PSD) validation
- Publication graphics: 2D endpoint density, discrete highest-density region (HDR) contours, scatter dot overlay, and raw overhead flight trajectories
- Complete atomic export bundle and configuration JSON import/export
- Appropriate conditional course strokes gained (SG) modeling

### Key Findings

1. **Core Scientific & Numerical Foundation**: **PASSED**.  
   The underlying physics, numerical solvers, 3D rigid delivery geometry (`club_geometry.py`), nominal matching (`nominal_matching.py`), 7-variable Gaussian noise generator (`noise.py`), academic plotting (`academic_plots.py`, `density.py`), and atomic export pipeline (`matched_export.py`) are fully implemented, rigorously unit-tested, and scientifically sound.
2. **Tile Integration & Embedded Launcher Registration**: **PASSED**.  
   `_embed_adapter.py`, `pyproject.toml`, `models.yaml`, and `launcher_manifest.json` are properly configured. `MainWidget` in `gui.py` embeds `MatchedStudyWidget` inside a dedicated tab ("Matched Delivery Study"). Clean lifecycle management, bounded shutdown, and lazy PyQt imports conform to repo contracts.
3. **Material Unmet UI Requirement in `matched_gui.py`**: **UNMET IN GUI PRESENTATION**.  
   While `matched_runner.py` computes conditional course strokes gained via `score_course_endpoints()` and saves it to `summary.json` under `course_scoring`, the GUI presentation layer `MatchedStudyWidget._completed()` in `matched_gui.py` **does not extract or display strokes gained anywhere in the UI view**. In contrast, the legacy tab (`gui.py`) displays Model SG in its summary table and a dedicated strokes-gained label.
4. **Tile Default Tab UX Inconsistency**: **OBSERVED CAVEAT**.  
   `models.yaml` describes the tile as featuring matched delivery, shaft rotation, strike variation, and covariance. However, `MainWidget` defaults to Tab 0 ("Independent Pattern Comparison", the Phase-1 1D face-variation model), requiring users to explicitly click Tab 1 ("Matched Delivery Study") to access the matched controls.
5. **Initial Speed SD Display Default**: **MINOR NUMERIC DISCREPANCY**.  
   `_DEFAULT_SD[2]` in `matched_gui.py` is initialized to `0.25` in SI m/s, which converts to `0.56 mph SD` on screen instead of `1.0` or `2.0 mph SD`. However, the control is a fully functional `QDoubleSpinBox` accepting 1.0 or 2.0 mph.

## 3. Deep-Dive Findings and Technical Observations

### Finding 1: Course Strokes Gained Display in `MatchedStudyWidget` (`matched_gui.py`)

#### Specification vs. Implementation
The user explicitly requested:
> *"integrated shot-pattern tile with ... appropriate conditional course SG. Review actual gui.py, matched_gui.py ... Find any material unmet explicit requirement or actual inconsistency."*

#### Backend Implementation (`matched_runner.py` & `course_score_vectors.py`)
In the backend, conditional course SG is fully implemented:
1. `course_score_vectors.py` defines hypothetical flat course scenarios:
   - **Driver**: 400 m hole, tee start, 30 m fairway corridor (`fairway_half_width_m = 15.0 m`), rough outside.
   - **Irons / Wedge**: fairway start at nominal straight carry (`target_x_m`), circular green (`green_radius_m = 15.0 m`), rough outside.
   - Lookups delegate to Mark Broadie (2011) PGA Tour baseline curves.
2. `matched_runner.py` (lines 308–326) invokes `score_course_endpoints()` and handles conditionality:
   ```python
   if len(indices) < request.n_shots:
       scoring["status"] = "conditional_only"
       scoring["full_population_status"] = "unavailable_unsupported_terminal_lies"
   else:
       scoring["full_population_status"] = (
           "available_under_hypothetical_course_assumptions"
       )
   ```
3. `matched_export.py` preserves `course_scoring` in `summary.json` and writes `scoring_baseline.json`.

#### Frontend Omission (`matched_gui.py`)
In `MatchedStudyWidget` (`matched_gui.py`):
1. There is no column, table, or label dedicated to strokes gained.
2. In `_completed()` (lines 647–715), the summary payload is loaded from `output_dir / "summary.json"`:
   - It reads `summary['target_x_m']`, `summary['nominals']`, and `summary.get('summary', {}).items()`.
   - It formats nominal face/path, speed in mph, delivered loft, residual in metres, supported shot counts, realized face/path correlation, and unsupported reasons into `self.result_label`.
   - It **never reads** `summary.get("course_scoring")` or `summary.get("scoring")`.
   - It never displays `mean_strokes_gained`, paired SG differences vs. Straight, or the course scenario description.
3. In contrast, the legacy presenter in `gui.py` (lines 169–181, 510–559):
   - Includes a "Model SG" column in `summary_table`.
   - Populates `mean_strokes_gained` per pattern.
   - Formats a detailed label: `Model-Conditional Strokes Gained: {scenario} ... Paired Difference vs. Straight (95% Monte Carlo Interval): {intervals}`.

**Impact**: A user running the Matched Delivery Study through the GUI cannot view the Strokes Gained results without navigating to the filesystem and opening `summary.json` or running offline report scripts.

### Finding 4: Default Speed SD Display Value

- In `matched_matrix.py` (lines 63–75), the matrix profiles define club speed SD as:
  - 1 mph (`0.44704 m/s`) for `shaft_speed1`, `combined1`, and `cov_...`
  - 2 mph (`2 * 0.44704 m/s`) for `shaft_speed2` and `combined2`
- In `matched_gui.py`:
  - `_DISPLAY["speed_mps"]` sets the control label to "Club Speed SD" with suffix "mph SD".
  - `_SCALE_TO_SI["speed_mps"] = 0.44704`.
  - However, `_DEFAULT_SD` (line 27) initializes index 2 to `0.25` (in SI m/s).
  - On line 218: `control.setValue(self._DEFAULT_SD[2] / self._SCALE_TO_SI["speed_mps"])` evaluates to `0.25 / 0.44704 ≈ 0.559 mph SD`.
- **Result**: When opened, the spinbox displays `0.56 mph SD` rather than 1.0 or 2.0 mph SD.
- The control is fully editable up to 20.0 mph SD, and config JSON import/export preserves exact values.

### Finding 5: Covariance & Positive-Semidefinite Validation

The 7-variable covariance implementation in `noise.py` and `matched_gui.py` is exemplary:
1. `NOISE_FIELDS` defines the exact canonical sequence:
   `("shaft_rotation_deg", "path_deg", "speed_mps", "contact_horizontal_m", "contact_vertical_m", "shaft_lean_deg", "attack_angle_deg")`.
2. The UI table in `matched_gui.py` locks the diagonal to `1.000` and mirrors off-diagonal edits symmetrically.
3. `NoiseSpec.__post_init__()` validates:
   - Symmetry (`np.allclose(corr, corr.T, atol=1e-12, rtol=0)`)
   - Unit diagonal (`np.allclose(np.diag(corr), 1.0, atol=1e-12, rtol=0)`)
   - Correlation bounds (`np.max(np.abs(corr)) <= 1.0 + 1e-12`)
   - Positive semidefiniteness (`float(np.linalg.eigvalsh(corr).min()) >= -1e-10`)
4. Sampling in `sample_paired_noise()` uses `np.linalg.eigh` with eigenvalue clipping of negative numerical roundoff, ensuring identical standard normal draws are transformed and reused across Straight, Draw, and Fade.
5. In `matched_gui.py`, attempting to run with a non-PSD matrix is caught synchronously and displays an explicit error message in `status_label` without starting background worker processes.

### Finding 6: Graphics Export Compliance

The graphics pipeline in `academic_plots.py` and `matched_export.py` fulfills every element of the visual requirement:
1. **Density**: 2D histogram probability density ($1/\text{m}^2$) computed by `shared_histogram_density()` on shared spatial grids, plotted via `pcolormesh`.
2. **HDR**: Discrete empirical highest-density-region contours for 50%, 80%, and 95% probability mass plotted via `axis.contour` with distinct line styles (solid, dashed, dotted).
3. **Scatter Overlay**: Deterministic colored scatter dots overlaying raw landing points (capped at $\le 600$ points with count disclosed in captions) via `axis.scatter`.
4. **Marginals**: 1D normalized histogram density marginals on top and right subplots.
5. **Overhead Trajectories**: Raw simulated flight paths plotted on shared axes to the target point without post-flight aiming via `write_overhead_trajectory_figure()`.
6. **Multi-Format Export**: All figures export simultaneously to PNG, PDF, and SVG.
7. **GUI Previews**: `MatchedStudyWidget` provides two dedicated tabs ("Endpoint Density" and "Raw Flight Trajectories") with smooth aspect-ratio scaling.
