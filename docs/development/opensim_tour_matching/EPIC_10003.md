# OpenSim Tour-Average Swing Matching Epic

Epic: [UpstreamDrift #10003](https://github.com/D-sorganization/UpstreamDrift/issues/10003).
Related: #9921 (Simscape matching), #9964 (engine equivalence), #9967 (native port).
Source baseline: `d03983d08`. Prepared 2026-09-12 UTC.
Status: **Plan Ready for User Check-In; Implementation Not Started**.

## Outcome and Scope

Deliver a repeatable OpenSim program that reads the tour-average driver C3D,
calibrates a documented golf model, matches observed body and club markers using
physical dynamics, and reproduces the result in an independent continuous forward
simulation. Final torque-actuated controls must be representable as one global
degree-six polynomial per declared actuator. Save cubic and flexible-control
intermediates as seeds, with their actual qualification status.

This is an addition to the active Pinocchio/Simscape effort. Native MATLAB runs
require R2025b. OpenSim does not require MATLAB. Muscle recruitment is a separate
extension; torque matching does not establish muscle forces. A human anatomical
OpenSim variant and a native Simscape-equivalent variant are separate models.
Neither a good IK overlay nor a converged optimizer proves a forward match.

scope. Cross-engine contracts belong in shared code only after checking existing
consumers. Exporters consume the native spec plus closure/actuation metadata;
plain URDF cannot carry every closed-loop and actuation semantic. Do not flatten
those semantics into undocumented approximations. Use engine-specific sidecars
and round-trip verification if URDF is introduced.

## Sequential Work Packages

Execute OS-0 through OS-6 in order. Each is a bounded lower-agent assignment with
one topic branch and claim. Create child issues from these packages immediately
before dispatch; do not assign the entire epic to an unattended small agent.

### OS-0: Runtime and Evidence Baseline

**Depends on:** user check-in. **Owns:** probes, manifests, documentation.

1. Inspect current OpenSim source and existing tests; run pure tests separately
   from native tests. Record skips as unavailable evidence, not passes.
2. Discover supported Python/OpenSim/Moco combination from official release
   guidance and an actual import. Record OS, executable, package versions and
   availability of Model, Manager, C3DFileAdapter, MocoTrack/MocoCasADiSolver.
3. Test load/init, a pendulum forward step, actuator pulse, and a small loop.
   Verify Moco can solve the chosen constraint types before choosing it.
4. Audit C3D units, axes, marker labels/masks, sample clock, analog channels,
   force-plate metadata, gaps, and event definitions. Never assume GRF exists.
5. Hash source, model and data. Save a baseline inventory and timings. Correct
   stale OpenSim status docs without claiming qualification.

**Red tests:** missing DLL/import, model load failure, absent Moco capability,
wrong source hash, incomplete observation window must fail qualification.
**Done:** actual native smoke receipts and complete capture/model inventory,
or a specific environment blocker with pure contract work preserved.

### OS-1: Marker, Frame, and Clock Contract

**Depends on:** OS-0. **Owns:** thin data adapter and contract tests.

1. Use the existing C3D loader once; retain raw bytes/hash and original clock.
2. Construct named marker observations in SI, retaining validity/confidence and
   distinguishing observed, gap-filled and unobserved samples. Record gap policy.
3. Export OpenSim TRC/table inputs with explicit world transform, handedness,
   length units and time origin. Verify inverse-transform round trip.
4. Define marker-to-body attachments and weights in versioned configuration.
   Do not derive club orientation from coincident/collinear markers silently.
5. Reuse body/club target and diagnostics APIs. Add narrow public extensions
   where existing schemas cannot preserve required coverage or provenance.

**Red tests:** mm/m factor, axis swap/reflection, shifted clocks, duplicate labels,
NaN masks, marker dropout, invalid quaternion and extrapolated observations.
**Done:** exact label/time/mask round trip, finite observed SI data, immutable
TRC/table manifest, coverage plot and baseline target overlay.

### OS-2: Model Variant and Physical Qualification

**Depends on:** OS-1. **Owns:** model configuration/export and native tests.

1. Inventory packaged coordinates, independent speeds, locks/couplers, muscles,
   coordinate actuators, optimal forces, contacts, damping and gravity.
2. Select and record the first variant. Recommended first deliverable is a
   torque-actuated golf model with physically declared two-hand club attachment.
   If exact cross-engine comparison is required, consume the native-derived
   Simscape spec; do not relabel the existing anatomical model as equivalent.
3. Check both grips, loop rank, coordinate singularities, positive inertias,
   masses, COM, length bounds, passive forces, and assembled initial q/u.
4. Verify control-to-physical-effort scaling and virtual work. Translational
   coordinates need forces; rotational coordinates need torques. Do not assume
   generalized speed equals coordinate derivative for every mobilizer.
5. For native-equivalent variant: same-pose frames, stationary unit pulses,
   moving-state accelerations and progressively longer identical-input replay.

**Red tests:** missing second grip, wrong force scale/sign, changed mass,
unassembled initial state, missing coordinate, unsupported constraint, or wrong
gravity must fail. A mock cannot satisfy native qualification.
**Done:** explicit variant manifest, reproducible native tests and a physical
capability report. Native equivalence remains false until its own gates pass.

### OS-3: Kinematic Feasibility and Geometry Calibration

**Depends on:** OS-2. **Owns:** calibration/IK settings and diagnostic reports.

1. Fit a bounded subset of segment lengths and fixed marker offsets across
   multiple observed poses. Separate calibration frames from validation frames.
2. Run constraint-aware IK for initial seeds and estimate the achievable marker
   error floor. Preserve joint limits, both hands and club dimensions.
3. Assess transition Jacobian conditioning and rank; report singular values and
   constraint errors. Unwrap coordinates consistently before smoothing speeds.
4. Use data-justified filtering; save its parameters and effect on marker error.
   Do not optimize geometry freely at each time sample.

**Red tests:** impossible rigid distances, inconsistent grip observations,
unbounded offset fitting, held-out marker deterioration and invalid derivatives.
**Done:** fixed calibrated model, explicit feasibility floor by marker/time and
an assembled initial state. Escalate impossible target/model requirements before
spending hours tuning efforts. IK output is a seed, not forward success.

### OS-4: Constraint-Aware Dynamic Tracking

**Depends on:** OS-3. **Owns:** one qualified solver adapter and replay runner.

1. Prefer a native Moco tracking pilot if OS-0 proved model-constraint support.
   It optimizes states and controls with dynamic constraints. Otherwise use the
   shared constrained multiple-shooting pathway after a small benchmark.
   Neither approach requires inverse dynamics as a prerequisite.
2. Define external loads explicitly. If force plates are absent, choose a
   documented contact model or penalized residual base actuation and disclose
   that inferred loads are non-unique. Never silently manufacture measured GRF.
3. Start with a short prefix and flexible continuous controls; extend through
   0.6, 0.7, 0.8 s and all observed motion using measured error/feasibility gates.
   Initialize later states from prior solutions but enforce defect constraints.
4. Penalize body/club errors, effort, effort rate and residual loads separately.
   Report residual magnitude and work relative to declared physical scales.
5. Replay each accepted control trajectory from one assembled initial state
   using Manager without target feedback, interior resets, or prescribed motion.

**Red tests:** nonzero shooting defects, reset-dependent candidate, clipped
controls, excessive residual loads, partial integration and false solver success.
**Done:** feasible full observed-interval tracking candidate, full timeline
continuous replay and per-marker residual report. Unobserved tail remains tagged.

### OS-5: Global Degree-Six Effort Profile

**Depends on:** OS-4. **Owns:** polynomial optimization/configuration tests.

1. Use a fixed normalized time domain and a well-conditioned degree-six basis.
   Save basis, coefficient ordering, units, domain, origin and actuator names.
2. Fit the flexible profile to degree six as an initializer, then optimize those
   coefficients against forward marker errors. Curve-fit alone is insufficient.
3. Keep early-prefix agreement as tolerances/weights, not infinite exact samples:
   a global polynomial cannot independently change its tail while staying exactly
   equal over an interval. Preserve candidate identity when horizon changes.
4. Refine all seven coefficients per actuator with multi-start and bounds on
   physical effort/rate, not arbitrary shared bounds on unlike coefficients.
5. Verify conversion to OpenSim controller and, only under a qualified physical
   mapping, Simscape's polynomial ordering. Test sampled effort and virtual work.

**Red tests:** time-domain rescaling, coefficient reversal, actuator permutation,
curve-fit degradation, validation at a different initial state and degree drift.
**Done:** one global degree-six profile per actuator passes independent forward
replay and declared marker/constraint/load gates. Preserve cubic/flexible seeds.

### OS-6: Repeatability, Visualization, and Handoff

**Depends on:** OS-5. **Owns:** CLI integration, acceptance report and docs.

Expose commands for prepare, qualify, calibrate, fit, replay, compare and resume
through the existing CLI/provider architecture. Treat these names as proposed
operations, not already available commands. A config selects source, model,
polynomial degree, initial candidate and tolerances. Two fresh runs reproduce
deterministic outputs within declared tolerances; changed seed/degree/data hashes
create new runs. Missing assets fail clearly. Native tests run in their opt-in lane.

Generate synchronized target/model 3D overlays, error-versus-time plots,
marker-wise metrics, observed coverage, loop error, effort/rate and residual-load
plots. Mark transition and missing intervals. The best candidate link must point
to a replay-qualified artifact, never just the smallest optimizer objective.
Benchmark startup and median/tail rollout/objective times on ControlTower with
matched accuracy; no unsupported promise that OpenSim is faster than Pinocchio.

**Red tests:** resume overwrites, corrupted checkpoint, wrong runtime/model hash,
failed candidate promoted to best, absent replay and missing asset relocations.
**Done:** complete handoff and a clean-machine reproduction receipt using the
declared model, capture and polynomial profile.

## Acceptance Policy

OS-0/OS-3 must freeze numerical tolerances before optimization in a versioned
configuration: observed body-marker RMS and p95, club RMS and p95, final observed
window errors, early-prefix regression, constraint position/velocity error,
integration success, residual loads/work, effort/rate and full timeline coverage.
Each metric includes units, sampling/mask definition and threshold rationale.
No tolerance is silently relaxed to pass a candidate. Report the measured IK
floor before promising millimeter accuracy that the model cannot represent.

At least one independent finer-accuracy replay must pass. Engine parity tolerances
are separate from marker-fit tolerances and must compare identical state/input
identities. Optimizer `success`, sparse endpoint agreement, or a zero-test native
lane cannot close this epic.

## Engineering and Turnover Rules

TDD: save the failing assertion/command, implement the smallest public boundary,
then record green tests and native evidence. DbC: validate dimensions, units,
finite values, monotone clocks, positive inertias and candidate identities before
simulation. LoD: optimizer calls an adapter facade, never nested SWIG internals.
DRY: one marker/time transform, objective definition, polynomial evaluator and
manifest implementation shared by consumers. Separate native tests from mocks.

Every work package updates [HANDOFF.md](HANDOFF.md) before commit. Check inbox,
claim its issue, record changed files and test commands, commit normally, and
record push/PR status. No hook bypass. Preserve interrupted jobs by PID/creation
time/command and immutable logs; a stale handoff alone does not prove a job live.
Large results live outside Git with hashes and restore instructions. A small
tracked receipt points to each authoritative artifact and source commit.
