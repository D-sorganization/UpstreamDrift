## Executive Read

UpstreamDrift is a 1.14M-LOC golf-biomechanics platform: ball-flight and contact physics (Python + an optional Rust kernel), a
motion-matching / inverse-dynamics stack (ZTCF/ZVCF, MOSAIC regressors, bunker-shot V&V), four physics-engine wrappers
(MuJoCo/Drake/Pinocchio/OpenSim), a FastAPI backend, a PyQt6 launcher, and a governance apparatus of 68 check scripts,
37 baseline/config files and 57 workflows. The newer numerical modules (ZTCF/ZVCF, GCI, rigid contact, MOSAIC regressor)
are mathematically careful and I verified two of them end-to-end. The strongest asset is honest provenance: the "Simscape
baseline" fixture openly records that it is MuJoCo output and tests fail closed on it.

The three things that would hurt most:

1. **Unauthenticated arbitrary file read** in the public `/launcher/logos/{filename:path}` route (`ASSETS_DIR / "/etc/passwd"`
   is `/etc/passwd`; demonstrated with TestClient). The repo already has a correct `resolve_contained_path` helper that this
   route does not use.
2. **The ball-flight simulator reports forces from one aerodynamic model while integrating another.** Positions come from the
   Rust Reynolds-crisis drag model with decaying spin; the per-point `acceleration`/`forces` are recomputed with the Python
   spin-polynomial drag and constant launch spin. `acceleration` is not `d(velocity)/dt` of the trajectory it is attached to.
3. **Governance that documents enforcement it does not perform.** `F401`/`F841` are still in `extend-ignore` (1,372 unused
   imports hidden) while CLAUDE.md says they are enforced; ~19.5k unmarked tests never run on `main` (the only always-on gate is
   `-m unit`); the hygiene test CLAUDE.md names as the enforcer of the Tools seam has no marker and fails on 43 files today;
   the ratchet baselines have never been lowered.

## Patterns and Approaches Worth Adopting

- **Property-based tests for kernels, not parity-by-construction.** The two best parity tests in the repo compare two
  consumers of the same Rust output (F-UD-038) or two call paths of the same Python (`test_counterfactual_golden_parity`).
  Hypothesis is already a dependency (38 files use it); point it at invariants: energy monotonicity under zero torque,
  `ztcf + M⁻¹τ == total`, `R(q)R(q)ᵀ = I` for every quaternion helper, `carry == landing_xy`.
- **One frame/unit convention object, enforced by types.** `canonical_layout.py` is the right idea; the F-UD-003 bug exists
  because `np.ndarray` carries no frame. A tiny `TangentVector(frame="pinocchio_local")` NewType, or `pint` quantities at the
  API boundary (degrees/radians, rpm/rad·s⁻¹ appear in `LaunchConditions`), turns these into type errors.
- **Lazy `__init__.py` everywhere.** Eager re-exports made a 650-line math module cost 1,720 imports (F-UD-021). Module-level
  `__getattr__` costs five lines and makes "can I import the math alone?" a CI check.
- **Ratchets must shrink automatically.** A ratchet whose tightening step is manual is a ceiling (F-UD-010). Run
  `--update-baseline` in the post-merge collate step the repo already has.
- **Measure the detector, not the count.** Before trusting "IMPROVED noqa_F401 711→201", ask whether the rule can fire
  (F-UD-004). A one-line meta-test — enable the rule in isolation and assert the count is non-zero — would have caught it.
- **Delete instead of shim.** 32 `DeprecationWarning` shims, a 20-root import redirect, `np.trapz` fallbacks under
  `numpy>=2.0`, 142 frozen Tools copies. Each shim is a place two truths coexist. The repo has no "shim expiry" check; the
  file-size budget's `expires_on` field is the pattern to reuse.
- **Governance budget.** The repo budgets file size, module size, docs size, PDF size, Docker size — but not the number of
  gates. Treat `scripts/ci/check_*.py` count and total LOC as a budget with the same ratchet discipline (F-UD-040).
- **Golden-master discipline.** The honest "withheld-not-validated" provenance file is the model; extend it: every fixture
  under `tests/fixtures/**` gets a `.provenance.json` with generator path + commit + input hash, and a test that refuses
  fixtures without one.
- **Mutation testing on the kernels.** `mutmut`/`cosmic-ray` on `ztcf_zvcf.py`, `rigid_contact.py`, `gci.py`, `cost.py` would
  show which of the ~47k tests actually constrain the maths (my guess: the oracle tests in `tests/unit/estimation/mosaic` do;
  most `is not None` tests do not).
- **Contract tests vs mock tests for engines.** 21 of 91 Drake/Pinocchio test files mock the engine; the real-engine lanes are
  all skip-gated. Add one tiny analytic model per engine (single pendulum, closed-form period) that runs in the always-on lane
  when the engine is present and is _required_ to run in the engine lanes (the `assert_required_parity_ran.py` idea, extended).
- **Agent instructions as code.** Eight dot-directories with hand-maintained copies is how `black .` survived (F-UD-015).
  Generate them from one source and test the generation, exactly as the repo does for `feature_parity.md`.
- **Public attack surface review per router.** `_PUBLIC_ROUTERS` is the right single list; add a test that every public route
  taking a path-like parameter calls `resolve_contained_path` (grep-level is enough), so F-UD-001 cannot recur in
  `matched_swings`/`lifting`.
