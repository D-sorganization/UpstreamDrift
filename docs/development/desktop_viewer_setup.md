# Desktop Viewer Setup, Shortcuts & App Identity

This guide documents the setup, architecture, and operational verification of desktop shortcuts, Windows taskbar identity, and favicon assets for the UpstreamDrift classic PyQt launcher and viewer suite.

---

## 1. Architecture Overview

### Canonical App Identity

- **AppUserModelID (AUMID):** `D-sorganization.UpstreamDrift`
- **Application Display Name:** `UpstreamDrift Golf Modeling Suite`
- **Canonical Shortcut Base Name:** `Golf Modeling Suite.lnk`

To ensure Windows properly groups running PyQt windows and displays the custom application icon on the Windows taskbar, the process explicitly registers its AUMID on startup via `ctypes.windll.shell32.SetCurrentProcessExplicitAppUserModelID` before creating any `QApplication` or Qt widgets:

```python
from src.launchers.app_identity import set_windows_app_user_model_id, APP_USER_MODEL_ID

set_windows_app_user_model_id(APP_USER_MODEL_ID)
```

### Windows Taskbar Pinning Note

Per Windows Shell design (Windows 7/10/11), programmatic taskbar pinning via COM verbs or registry manipulation is strictly prohibited and intentionally blocked by the operating system to prevent software bloat. Instead, Windows associates pinned shortcuts or active running windows with the application icon purely through the matching **AppUserModelID**. Once installed in the Desktop or Start Menu, users can right-click the shortcut or running window to pin it to their taskbar.

## 2. Icon & Favicon Asset Hierarchy

Application icons are resolved deterministically using a prioritized candidate search:

1. `src/launchers/assets/golf_robot_cropped.ico` (multi-resolution Windows ICO containing 16x16, 32x32, 48x48, 64x64, 128x128, 256x256).
2. `src/launchers/assets/golf_robot_cropped.png` (high-resolution source PNG).
3. `ui/public/favicon.ico` (web UI favicon, synchronized with desktop icon).

### Favicon Synchronization

The web UI at `ui/public/favicon.ico` and `ui/index.html` matches the desktop launcher icon so that local browser-based views or remote client sessions present the exact same brand identity:

- HTML link tag: `<link rel="icon" type="image/x-icon" href="/favicon.ico" />`
- Binary parity: Verified by unit tests (`tests/unit/launchers/test_app_identity.py`).

## 3. Creating & Managing Shortcuts

### Automated CLI Setup

To install or refresh both Desktop and Start Menu shortcuts idempotently:

```bash
python launch_upstream_drift.py --install-shortcuts
```

Or directly using the Python module:

```bash
python -m src.launchers.desktop_shortcuts
```

### PowerShell Helper Scripts

Convenience wrapper scripts are provided in the `scripts/` directory:

- `scripts/create_shortcut.ps1`: Installs both Desktop and Start Menu shortcuts for the launcher suite.
- `scripts/create_golf_robot_shortcut.ps1`: Dedicated helper for the golf robot viewer shortcut.

### Shortcut Properties

Shortcuts generated by `ShortcutManager`:

- **Target Path:** Path to Python executable (e.g., `pythonw.exe` for GUI or `python.exe`).
- **Arguments:** Full path to `launch_upstream_drift.py`.
- **Working Directory:** Repository root.
- **Icon Location:** Canonical `.ico` file path.
- **Description:** `UpstreamDrift Golf Modeling Suite Launcher`.

## 4. Verification and Troubleshooting

### Inspecting Existing Shortcuts

You can inspect shortcut target, arguments, working directory, and icon path programmatically using `ShortcutManager.read_shortcut_metadata`:

```python
from src.launchers.desktop_shortcuts import ShortcutManager
import pathlib

desktop_lnk = pathlib.Path.home() / "Desktop" / "Golf Modeling Suite.lnk"
meta = ShortcutManager.read_shortcut_metadata(desktop_lnk)
print(meta)
```

### Common Issues

1. **Generic Python Icon in Taskbar:**
   - Cause: `SetCurrentProcessExplicitAppUserModelID` was not invoked before `QApplication` instantiation, or Python executable was launched directly without AUMID registration.
   - Fix: Always launch via `python launch_upstream_drift.py` or the desktop shortcut.
2. **Missing Start Menu Shortcut:**
   - On Windows, Start Menu shortcuts are placed in `[Environment]::GetFolderPath("Programs")` (`AppData\Roaming\Microsoft\Windows\Start Menu\Programs`). Running `--install-shortcuts` ensures both Desktop and Start Menu locations are created.
