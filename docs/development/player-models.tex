\section{Published Dimensions and Uncertainty}
Tiger's selected prior is 73 inches and 185 pounds, exactly 1.8542 metres and
83.91458845 kilograms, from his official biography. The 2005 PGA Tour guide
instead lists 74 inches and 180 pounds; neither establishes his exact 2000
capture dimensions. Hogan's PGA Tour profile lists 68 inches and 150 pounds,
exactly 1.7272 metres and 68.0388555 kilograms; the PGA retrospective lists
145 pounds (65.77089365 kilograms). These are conflicting published values,
not confidence intervals. Full URLs and era notes are retained in
\texttt{src/config/player\_appearance\_presets.json}.

\section{Construction and Compatibility}
Segment lengths and inertias use the existing de Leva/OpenSim priors, with
explicit stature-scaled thigh and shank targets on both legs (the template
otherwise retains unequal fixed leg lengths), and
\texttt{match\_subject\_mass=True}. Human solid masses sum to the selected
mass after subtracting the recorded club mass. Segment proportions are not
measured on either golfer. The resulting driver has the current reference's
52-coordinate contract; dimension changes intentionally change its physics.
An existing C3D trajectory or torque history must be refitted to a newly sized
model. By contrast, supplying \texttt{base\_spec} to the exporter keeps the
entire input physics document and applies only the visual appearance.

\section{Visual Body Build}
The optional appearance field \texttt{body\_build} is a dimensionless artistic
control in $[-1,1]$, with zero reproducing the original fitted skin exactly.
For hip-centred fitted coordinates $(x,y,z)$ in metres, neck height $H$ and
positive half-shoulder spacing $S$, set $h$ to a smoothstep window from
$-0.14H$ to $0.10H$ and from $0.72H$ down to zero at $H$. Set $l$ to one
at $|y|\le0.8S$, falling smoothly to zero at $1.7S$. The transverse map is
$(x,y,z)\mapsto(sx,sy,z)$, where $s=1+0.18\,bhl$. The neck and extremities
therefore stay anchored and body, shirt and trousers share the same surface
change before clothing offsets. The skeletal landmark locations, weights,
faces and native rigid-body properties stay fixed. This control is not a
measured body composition or a prediction from listed mass; render checks
are required for each pose and outfit, especially arm/torso overlap.
Reproduce the topology and native dynamics tests with:
\begin{verbatim}
PYTHONPATH=.:vendor/ud-tools/src python -m pytest tests/unit/model_appearance/test_body_build.py
\end{verbatim}
\section{Cap Style Override}
The batch exporter accepts \texttt{--cap-style} from the live \texttt{CAP\_STYLES} schema choices. This changes only the appearance
sidecar; the profile remains unchanged and the receipt records an explicit
\texttt{head.cap\_style} override. The override is rejected before any
output is written when it is unknown, and cannot be combined with
\texttt{--render-existing} because that mode does not regenerate XML.
Flat and newsboy caps use a short 0.12-head-length peak; a profile's straw

\section{Sized-Candidate Frame Inertia Estimate}
The sized-candidate builder accepts a dimensionless \texttt{frame\_build}
$b\in[-1,1]$, set by the catalog's explicit physical \texttt{frame\_prior}; it
is zero when unknown. The separate visual \texttt{body\_build} does not set
the physical prior. Direct sized-builder use remains independent. Existing fitted specs supplied for appearance-only export
are not rebuilt or changed. For nonzero $b$, three de Leva trunk solids
(pelvis, middle and upper trunk) receive an estimated change in transverse
mass distribution, while segment mass and COM remain fixed. In each supported
upright body frame, with identity solid placement, let
\[ C=\tfrac{1}{2}\operatorname{tr}(I)\,\mathbf{1}-I,\quad
 A=\operatorname{diag}(1+0.18b,1+0.18b,1),\quad
 C'=ACA^T,\quad I'=\operatorname{tr}(C')\mathbf{1}-C'. \]
Here $I$ is the original COM inertia (kg m$^2$) and $C$ the integrated second
moment. Positive-definite $C$ and invertible $A$ ensure positive principal
second moments and strict inertia triangle inequalities. Missing torso solids,
nonidentity torso placements, a nonvertical torso axis, and nonphysical initial
tensors raise an error. The additional upper-arm, forearm, thigh and shank estimate is
documented in \texttt{player-limb-inertia.tex}. Geometry, segment mass, COM,
joint axes and unlisted segments remain unchanged; the export recomputes its upper-body hash and records the
build and scale in the calibration receipt. The scale is a bounded heuristic
consistent with the visual control's maximum amplitude, not the integral of
its taper and not a measured body composition or individual inertia. De Leva
population averages and published total mass remain priors; no subject-specific
segment scans or distribution data are established. Changed dynamics require
refitting captured motion. Reproduce the mass, positivity and native inertia
matrix tests with:
\begin{verbatim}
PYTHONPATH=.:vendor/ud-tools/src python -m pytest tests/unit/model_appearance/test_player_frame_inertia.py
\end{verbatim}
\subsection{Source-Attributed Frame Prior}
An opt-in \texttt{height\_mass} prior selects a profile source and assumes
equal average density and geometrically similar proportions relative to
$H_0=1.71$ m and $M_0=78$ kg. For listed height $H$ and mass $M$, the
transverse scale and bounded input are
\[s=\sqrt{(M/M_0)(H_0/H)^3},\quad b=\operatorname{clip}((s-1)/0.18,-1,1).\]
The source and era, raw scale, bound saturation and model assumption are
recorded in the export receipt. A numeric \texttt{override} requires a
written rationale; an absent prior means unknown, not a measured zero.
Listed dimensions may not match the depicted era; composition, segment girths
and subject-specific inertias are unmeasured. Bounds and alternatives such as
$b\pm0.25$ are illustrative sensitivity cases, not confidence intervals.
The tapered visual shape and uniform transverse inertia transforms have
different geometry even when their parameters happen to be equal.
\section{Reproduction and Acceptance}
From the repository root, initialize the pinned Tools submodule and set
\texttt{PYTHONPATH=.:vendor/ud-tools/src} and \texttt{MUJOCO\_GL=egl} on Linux.
\begin{verbatim}
from pathlib import Path
from src.shared.python.model_appearance.player_models import export_player
export_player("tiger_woods", Path("output/tiger"))
export_player("ben_hogan", Path("output/hogan"))
export_player("tiger_woods", Path("output/capture_skin"),
              base_spec=Path("existing_match.json"))
\end{verbatim}
Outputs are native MJCF, physical JSON, an appearance sidecar and a receipt.
A separate \texttt{model.visual.json} embeds appearance explicitly for exact
Necromatcher native-resource verification; the input physics stays unchanged.
Tests check published priors, actual total human mass, current model selection,
distinct face settings, independent profile reads, unchanged supplied specs
and compiled native dynamics under skin changes. The first tests failed on
the absent player module and absent \texttt{base\_spec} API, respectively.
An additional red test found fixed template leg lengths; the corrected build
checks actual hip--knee and knee--ankle distances against the declared priors.
These software gates do not qualify historical motion or precise likeness.
