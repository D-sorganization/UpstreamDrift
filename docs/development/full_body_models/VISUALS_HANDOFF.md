## Rules for Every Step

TDD (failing test first, then code), DbC (validate shapes, finiteness, names;
raise `ValueError`), LoD (adapters consume `VisualSkeleton`, never reach into
engine internals from viewers), DRY (no second skeleton derivation, no second
capture loader, no second replay format). Lease the issue you take, update
`HANDOFF.md` beside this file and the DL-#10062 entry in every implementation
commit, and archive any rendered evidence with a receipt naming the candidate
hash. Never call a rendered playback a match; it is a visual of a stated
candidate.

## Step 3: Tour Matching Viewer Tile (Launcher, Engine-Agnostic)

Goal: a launcher tile that plays a replay against the capture with the
skeleton, in-app, on this Windows machine, without any engine installed.

Red tests first (tests/unit/tools/test_tour_matching_viewer_core.py):

1. `load_replay(path)` accepts the native `returned-replay.npz` layout
   (`time_s`, `native_state` (T, 2n), `markers_m`, `target_m`, `valid`) and an
   OpenSim IK `.mot` (columns are coordinate names); rejects mismatched frame
   counts, non-monotone time, unknown coordinate names.
2. `body_poses_from_state(spec, q)` returns a 4x4 pose per body from the spec
   joint tree using the same primitive semantics as the engines (Px, Py, Pz
   translations then Rx, Ry, Rz intrinsic rotations in the base frame); test
   against the packaged MuJoCo model's `xpos`/`xmat` for 20 random states to
   1e-9 (MuJoCo is installed here; skip cleanly if not).
3. `viewer_frame(spec, replay, i)` returns world capsule segments plus target
   and model marker arrays for frame `i`, using `skeleton_world_segments`.

Then implement `src/tools/tour_matching_viewer/` as a package (`__init__`,
`__main__`, `core.py` pure data, `gui.py` PyQt6 with matplotlib 3D axes or a
`QOpenGLWidget`), a `models.yaml` tile (`launcher.category: tool`, status
`beta`), and an `_embed_adapter.py` plus entry point per AGENTS.md section D.
The GUI shows: candidate hash and engine in the title, play/pause/scrub,
target markers (black) versus model markers (engine colour), skeleton
capsules, ground plane, per-frame valid-marker RMS. Keep GUI code
untestable-by-design thin; everything numeric lives in `core.py`.

Done gate: opens from the launcher, plays `returned81` and the OpenSim OS-3b
IK `.mot`, screenshot committed under `evidence/viewer/` with receipt.

## Step 4: Same-Input Replays of the Returned81 Candidate in MuJoCo and Drake With Video

Goal: three engines animating one candidate.

- MuJoCo (local): replay the returned81 polynomial with the qualified
  `NativeMujocoModel` rigid-closure adapter (upper-body model, not full body),
  record q(t), write the shared replay NPZ, then render with the visual layer
  through `mujoco.Renderer` to `evidence/replays/mujoco_returned81.gif`. Report
  the five metrics (whole, early, terminal, clubhead, pelvis yaw) and the
  marker difference versus the Pinocchio replay per sample. Red test: the
  replay NPZ writer/reader roundtrip and the metric function against the
  archived Pinocchio numbers (whole 26.366 mm, terminal 46.305 mm).
- Drake (ControlTower): first close the failed 0.85 s run-18 full-state parity
  (`drake_native_matching/reproduction/diagnose_run18.py`), then replay
  returned81 with the KKT adapter, write the same NPZ, render via meshcat
  (`pip install meshcat` in the Drake runtime) with the shared skeleton
  translated to meshcat cylinders and spheres (`skeleton_world_segments`),
  capture frames to GIF. Launch with `systemd-run --user` and `run_job.py`.
- Pinocchio (ControlTower): render the existing `returned-replay.npz` the same
  way for a like-for-like third animation.

Done gate: three GIFs of the same candidate hash under `evidence/replays/`
with receipts, plus a cross-engine table of the five metrics.
