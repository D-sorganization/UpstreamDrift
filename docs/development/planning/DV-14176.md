# DV-14176: Putting Analytics Skill Preset Calibration Against Published Reference Data

Source: [UpstreamDrift#14176](https://github.com/D-sorganization/UpstreamDrift/issues/14176) (child of epic [#14168](https://github.com/D-sorganization/UpstreamDrift/issues/14168)). Status: **deferred**. Board: **pending**. Disposition: **split**. Kind: external-review.

## Rationale

Calibrating the putting presets needs reference tables this repository does not hold
and simulator pieces on unmerged branches. Calibrating against the model's own output
would be circular, so it waits. The registry and harness stay in the open issue.

## Existing Capabilities and Evidence

Software evidence only (`src/shared/python/putting_validation/` and tests); no
calibration. Finding: the anchors in the comment in
`src/shared/python/sg_optimizer/shot_model/putting.py` (about 99, 50 and 7 percent at
3, 8 and 30 ft) do not match the logistic itself (94.6, 51.8 and 2.4 percent). An
expected-failure test records this; resolving it needs the Broadie table A.5 values.

## Resources and Prerequisites

- Broadie (2014) table A.5 tour make percentage and expected putts, entered from the
  published source with page references: **unavailable**.
- A PGA Tour ShotLink extract (license permitting use here) and published amateur
  make-rate tables for scratch, 10 and 20 handicap: **unavailable**.
- Batch-roll putting simulator (#14171) and skill sampler (#14169): **unmerged**.

## Acceptance Criteria

Calibrate the tour, scratch, 10 and 20 handicap presets so the simulated make-percentage
curve falls within the reference band, and show the tour E_player(d) is within tolerance
of the tour expected-putts table, recording fit and residuals. No preset is called
calibrated without that provenance record; if licensed data stays unavailable this entry
stands instead of tuning to the model's own output. Full criteria: `catalog.json`.
