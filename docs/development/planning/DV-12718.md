# DV-12718: NSX-89 Simscape Per-Frame Linearization Export in MATLAB R2025b

Source: [UpstreamDrift#12718](https://github.com/D-sorganization/UpstreamDrift/issues/12718) (Parent Epic: [UpstreamDrift#12593](https://github.com/D-sorganization/UpstreamDrift/issues/12593)). Status: **deferred**. Board: **pending**.
Disposition: **split**. Kind: research-idea.

## Rationale and Expected Value

The tangent linearization `(F_t, G_t)` of the closed-loop dynamics needs derivatives of the
constrained acceleration with the reaction re-solved, evaluated at perturbed states. The
NSX-55 Simscape export (DV-12583, `simscape-closed-loop-snapshot/v1`) is a snapshot grid of
`M`, `h`, `J_c` and `Jdot_v` at fixed states; it cannot be re-evaluated at a perturbed
state, so no derivative, finite difference or interpolation can be taken from it. The
Simscape derivative capability is therefore **NONE** in
`derivative_capability.default_registry()`, and every variability output that would
consume Simscape derivatives is `UNAVAILABLE` with that reason. This is the fail-closed path
of issue #12718. It depends on DV-12583: no golf-model snapshot export exists either.

## Existing Capabilities and Evidence

- The capability seam: `loop_nullspace/derivative_capability.py` declares `simscape` as
  `NONE` with the reason above, and `unavailable_derivative_record` turns that into an
  all-NaN `UNAVAILABLE` `QuantityRecord`.
- The payload gate: `loop_nullspace/simscape_linearization.py` defines
  `simscape-trajectory-linearization/v1` and refuses any file that is not a golf-model
  `matlab_export` from exactly R2025b (R2026a and older releases, the verification rig
  and synthetic fixtures are refused) or that lacks solver settings and state mapping.
- No MATLAB run of any kind was made for this record. The session host cannot run
  MATLAB R2025b, and nothing here is MATLAB evidence.

## Required Export Contents

A per-frame R2025b `linearize` export of the golf probe variant (the DV-12583 model) must
carry, in `simscape-trajectory-linearization/v1`:

- `provenance`: `provenance_kind` `matlab_export`, `model_scope` `golf_model`,
  `matlab_release` exactly `R2025b`, a `matlab_version` string naming `(R2025b)`,
  `model_file`, `model_sha256` of the saved model and `exported_at`.
- `solver_settings`: solver, tolerances and step settings used for the operating point
  and the `linearize` call.
- `state_mapping`: `q_names`, `v_names` and `input_names`, the order of `x = (q, v)` and `u`
  in `A` and `B`, mapped to the canonical coordinate order of the snapshot export.
- `frames[]`: for each frame `q`, `v`, `tau`, `A` (`2 nq x 2 nq`) and `B` (`2 nq x nu`).

## Resources and Prerequisites

- The DV-12583 probe-capable open-tree golf variant, built and saved in R2025b — **unbuilt**.
- An R2025b host whose licence admits the variant and Simulink Control Design `linearize` — **untested**.
- A same-topology independent reference linearization (Pinocchio or OpenSim adapter, NSX-85..88) — **available once topologies match**.

## Acceptance

1. The export file passes `parse_simscape_linearization` and its `model_sha256` matches the saved model.
2. `A` and `B` agree with the same-topology reference tangent linearization within the registry tolerances, with the closure Jacobian and reaction re-solved.
3. Only then may the `simscape` derivative declaration move off `NONE`, with the feature-parity entry updated.
4. A planar-rig export, a synthetic fixture, or any R2026a result is never acceptance evidence.
