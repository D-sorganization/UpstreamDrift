# BunkerShot3D Designer Workbench & API

**Issues #9545, #12536. Framework: NASA-STD-7009B / ASME V&V 20-2009.**

The BunkerShot3D workbench provides fast, bounded wedge sole exploration in bunker sand.
It pairs an interactive PyQt desktop GUI (`src.tools.bunker_shot_gui`) with a versioned headless HTTP API (`/tools/bunker-workbench/v1`), both driving the exact same underlying headless model (`src.tools.bunker_shot_gui.model.WorkbenchModel`) and continuum dynamic 3D-RFT (F0) physics solver.

---

## 1. Architecture & Feature Overview

The workbench exposes identical physics, verdict tiers, and validity markings across both desktop and web surfaces:

- **Headless Solver Core**: Evaluates wedge sole geometry, sand conditions, and delivery kinematics using dynamic 3D-RFT.
- **Validity & Credibility Stamps**: Every result, exported figure, VTK rendering, and saved record carries an in-frame validity stamp and SHA-256 canonical digest. Results are stamped with their fidelity tier (F0) and envelope standing.
- **Desktop Workbench (`bunker_shot_gui`)**: Interactive PyQt application featuring design parameter controls, sand/delivery condition editors, interactive 3D VTK viewport embedding clubhead and sand furrow geometries, and stamped export actions.
- **Versioned Web API (`/tools/bunker-workbench/v1`)**: Thin FastAPI endpoints providing synchronous single-shot evaluation (`/v1/evaluate`), A/B comparison sweeps (`/v1/compare`), and record integrity verification (`/v1/verify`).

## 2. Replayable V1 Workbench API Example

The following self-contained Python script illustrates how to execute a nominal evaluation via the versioned API router, inspect results, export artifacts, and verify record integrity:

```python
"""Replayable example of BunkerShot3D v1 workbench API usage."""

from fastapi import FastAPI
from fastapi.testclient import TestClient

from src.api.routes.bunker_workbench import router
from src.tools.bunker_shot_gui.export import (
    load_workbench_evaluation,
    save_workbench_evaluation,
)

# 1. Mount the versioned router in an application client
app = FastAPI()
app.include_router(router)
client = TestClient(app)

# 2. Define evaluation request payload
payload = {
    "handedness": "right",
    "design": {
        "name": "Wedge-58M",
        "grind_preset": "sm9_58_m",
    },
    "sand": {
        "preset": "firm",
    },
    "swing": {
        "clubhead_speed_mps": 25.0,
        "attack_angle_deg": -6.0,
    },
    "objective": "exploratory",
}

# 3. Execute nominal evaluation (F0 dynamic 3D-RFT solve)
response = client.post("/tools/bunker-workbench/v1/evaluate", json=payload)
assert response.status_code == 200, response.text
record = response.json()

# 4. Inspect physical outcomes and validity metadata
print(f"Schema:   {record['schema_version']}")
print(f"Tier:     {record['tier']} ({record['tier_model']})")
print(f"Verdict:  {record['verdict']['status']} - {record['verdict']['headline']}")
print(f"Peak Fz:  {record['shot']['peak_force_n']:.1f} N")
print(f"Impulse:  {record['shot']['impulse_n_s']:.2f} N*s")
print(f"Max Dep:  {record['shot']['max_depth_m'] * 1000.0:.1f} mm")
print(f"Stamp:    {record['stamp']}")
print(f"Digest:   {record['digest']}")

# 5. Save evaluation to disk and reload with fail-closed integrity checks
saved_path = save_workbench_evaluation(record, "nominal_eval.json")
reloaded = load_workbench_evaluation(saved_path)
assert reloaded["digest"] == record["digest"]

# 6. Verify record integrity through the API endpoint
verify_response = client.post("/tools/bunker-workbench/v1/verify", json=reloaded)
assert verify_response.status_code == 200
assert verify_response.json()["valid"] is True
```

## 3. Python Headless Model Example

For direct programmatic execution without an HTTP layer, the desktop and API shared core can be invoked directly:

```python
from src.tools.bunker_shot_gui.design import SandCondition, SwingSetup, WedgeDesign
from src.tools.bunker_shot_gui.model import WorkbenchModel

model = WorkbenchModel()
design = WedgeDesign(name="Wedge-58M", grind_preset="sm9_58_m")
sand = SandCondition(preset="firm")
swing = SwingSetup(clubhead_speed_mps=25.0, attack_angle_deg=-6.0)

evaluation = model.evaluate(design, sand, swing)
print("Nominal peak force:", evaluation.nominal.peak_force_n)
print("Envelope status:   ", evaluation.verdict.status.value)
```

## 4. Stamped Visual & VTK Exports

Exports generated by the workbench are stamped in-pixel and verified via SHA-256 digests:

- **2D Figure Export (`export_figure`)**: Writes Matplotlib views as PNG with in-pixel watermark stamp and metadata JSON in a PNG text chunk.
- **VTK Frame Export (`export_vtk_stamped_frame`)**: Captures PyVista/VTK 3D scenes as PNG carrying the validity stamp and SHA-256 header digest.
- **VTK Animation Export (`export_vtk_stamped_animation`)**: Exports animated GIF sequences of penetration and sand deformation, embedding the validity stamp in the GIF comment block.
- **Verification (`read_export`, `read_animation_export`)**: Re-reads exported images/animations and fails closed (`ExportIntegrityError`) if the file was modified, unstamped, or altered.

## 5. Explicit Physical Limitations & Constraints

In compliance with ASME V&V 20-2009 and NASA-STD-7009B, all calculations state the exact boundary of credibility:

### 1. Froude Limit Refusal & Out-of-Envelope Operation

- Dynamic Resistive Force Theory (3D-RFT) is calibrated in literature for low-speed penetrations ($Fr \le 0.4$, intrusion speeds $\le 1.44\text{ m/s}$).
- At greenside bunker speeds ($25\text{ m/s}$ on a $100\text{ mm}$ clubhead), the operation runs at $Fr \approx 25.2$ (~63x outside published RFT envelope) and $Fr \approx 113$ on the leading edge.
- Published RFT coefficients are uncalibrated initial estimates. The single most influential constant, $\lambda$, is known to within a factor of nearly three. Dynamic structural correction $\delta_h$ is a regularized convention rather than a measured wedge parameter.
- **Implication**: The solver is verified for comparative sole geometry ranking. It must **not** be quoted as predicting absolute physical impact forces.

### 2. Uncalibrated Sand-to-Ball Momentum Transfer

- Sand-to-ball momentum transfer (`bunkershot3d.ball.splash`) has no physical stroke measurements admitted to the transfer register (`docs/bunkershot3d/transfer-qualification.md`).
- Every launch and carry calculation is unconditionally floored at `BEYOND_VALIDATION`.
- Any playability or carry objective is strictly exploratory (`predictive: false`). Attempting to submit or claim a `predictive: true` record is rejected fail-closed with 422 Unprocessable Entity or `ExportIntegrityError`.

### 3. Handedness

- Current kinematics and CAD profile projections support right-handed deliveries (`handedness: "right"`). Left-handed requests are refused at the boundary with HTTP 422.

### 4. Deferred 3-D Grain DEM Producer

- A full discrete element method (DEM) 3-D grain producer via Project Chrono (`pychrono`, conda-only) was deferred by owner ruling on 2026-10-14.
- Tracked in `docs/development/deferred-catalog-bundle.json` under `BS3D-F3-GRAIN-PRODUCER`.
- Design iteration relies on the fast continuum F0 dynamic 3D-RFT solver for real-time responsiveness.
